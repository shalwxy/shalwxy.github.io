## 문제

온라인 게임 길드의 암구호로 쓸 두 단어가, 서로 철자 구성만 같고 순서만 다른 단어(애너그램)인지 확인한다. **대문자와 소문자는 서로 다른 글자로 구분한다.**

- 두 단어의 길이는 서로 같고, 각각 100을 넘지 않는다
- 입력: 첫 줄에 첫 번째 단어, 둘째 줄에 두 번째 단어
- 출력: 애너그램이면 `YES`, 아니면 `NO`

```
입력                출력
PpSQrPS             YES
SQrpSPP
```

두 단어 모두 P 2번(대문자), p 1번(소문자, P와는 다른 글자로 센다), S 2번, Q 1번, r 1번으로 구성이 똑같다. 순서만 다를 뿐 같은 글자를 같은 개수만큼 쓰고 있어 애너그램이다.

> 출처: 인프런 [자바(Java) 알고리즘 문제풀이 입문: 코딩테스트 대비](https://www.inflearn.com/course/자바-알고리즘-문제풀이-코테대비)의 [1140번 문제](https://oj.inflearn.com/problem/1140)를 소재와 예제만 바꿔 재구성했다.

## 공통 코드

아래 시도들은 입력을 읽고 결과를 출력하는 부분을 공유한다. 각 시도에서는 애너그램 여부를 판별하는 `isAnagram` 메서드만 다르다.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String s1 = sc.next();
        String s2 = sc.next();

        System.out.println(isAnagram(s1, s2)); // 로직은 각 시도 참고
    }
}
```

## 시도 1 — 알파벳 범위를 배열로

### 접근

[투표로 뽑힌 간식 찾기](/lab/engineering/algorithm/1210010/)처럼 문자를 배열 인덱스로 센다. 다만 이번엔 후보가 5개로 고정돼 있지 않고 대문자와 소문자 알파벳 전체가 올 수 있다. `'A'`(65)부터 `'z'`(122)까지를 한 배열에 담으려고, `'z' - 'A' + 1`칸짜리 배열 두 개를 만들어 각각 센 뒤 통째로 비교했다.

```java
public static String isAnagram(String s1, String s2) {
    int[] cnt1 = new int['z' - 'A' + 1];
    int[] cnt2 = new int['z' - 'A' + 1];
    for (char x : s1.toCharArray()) cnt1[x - 'A']++;
    for (char x : s2.toCharArray()) cnt2[x - 'A']++;

    for (int i = 0; i < cnt1.length; i++) {
        if (cnt1[i] != cnt2[i]) return "NO";
    }
    return "YES";
}
```

### 결과

**성공** — 예제에서 `YES` 출력.

복잡도: 시간 O(L), 공간 O(1)(`'z' - 'A' + 1`, 곧 58이라는 고정 크기). L은 단어 길이.

### 분석

배열 크기를 58이라는 숫자로 바로 적지 않고 `'z' - 'A' + 1`이라는 식 그대로 써서, 왜 이 크기인지는 코드만 보고도 알 수 있다. 그래도 `'Z'`(90)와 `'a'`(97) 사이에는 실제로 쓰이지 않는 칸이 여섯 개 끼어 있어서, 배열 크기 중 상당수는 애초에 채워질 일이 없다. 알파벳이 아닌 다른 문자가 섞이면 이 범위 계산부터 다시 해야 한다.

## 시도 2 — 해시맵 두 개를 만들어 비교

### 접근

문자를 배열 인덱스로 바꾸는 계산 없이, 각 단어의 문자 개수를 해시맵에 그대로 센 뒤 두 맵이 완전히 같은지 비교했다.

```java
import java.util.HashMap;
import java.util.Map;

public static String isAnagram(String s1, String s2) {
    Map<Character, Integer> map1 = new HashMap<>();
    Map<Character, Integer> map2 = new HashMap<>();
    for (char x : s1.toCharArray()) map1.put(x, map1.getOrDefault(x, 0) + 1);
    for (char x : s2.toCharArray()) map2.put(x, map2.getOrDefault(x, 0) + 1);

    return map1.equals(map2) ? "YES" : "NO";
}
```

### 결과

**성공** — 예제에서 동일하게 `YES` 출력.

복잡도: 시간 O(L), 공간 O(실제로 나온 글자 수). 배열의 "쓰이지 않는 칸"이 사라지고, 알파벳이 아닌 문자가 와도 그대로 동작한다.

### 분석

알파벳 범위에 맞춘 배열 크기 계산은 사라졌지만, 맵을 **두 개** 만들었다. 두 단어 각각의 분포를 따로 센 다음에야 비교하므로, 저장 공간이 들어온 글자 종류의 두 배로 늘어난다. 그리고 `map1.equals(map2)`는 내부적으로 모든 항목을 맞춰봐야 끝나서, 둘째 글자에서 이미 다른 게 확실해져도 끝까지 다 센 뒤에야 `NO`를 알게 된다.

## 시도 3 — 해시맵 하나로 세고, 바로 차감하며 확인 (채택)

### 접근

s1의 분포만 맵 하나에 세워두고, s2를 훑으면서 그 자리에서 바로 하나씩 **차감**한다. s2의 어떤 글자가 맵에 없거나 이미 0이면, 그 순간 `NO`로 끝낸다.

```java
public static String isAnagram(String s1, String s2) {
    Map<Character, Integer> map = new HashMap<>();
    for (char x : s1.toCharArray()) map.put(x, map.getOrDefault(x, 0) + 1);

    for (char x : s2.toCharArray()) {
        if (!map.containsKey(x) || map.get(x) == 0) return "NO";
        map.put(x, map.get(x) - 1);
    }
    return "YES";
}
```

### 결과

**성공** — 예제에서 동일하게 `YES` 출력.

복잡도: 시간은 최악의 경우(두 단어가 끝까지 똑같을 때) O(L), 공간 O(s1에 나온 글자 종류). 불일치를 만나면 그 즉시 반환하므로, `NO`인 경우는 보통 L보다 더 빨리 끝난다.

### 분석

시도 2의 맵 두 개 중 하나는 꼭 필요하지 않았다. s1의 분포를 "쓸 수 있는 재고"로 보면, s2는 그 재고를 하나씩 꺼내 쓰는 셈이다 — 맵을 새로 만들 필요 없이 s1의 맵에서 바로 차감하면 된다. 재고가 없거나 다 썼는데 더 꺼내려 하면 그 자리에서 아나그램이 아니라고 판정된다.

다만 이 "차감" 판정은 **두 단어의 길이가 같다는 조건**에 기댄다. 길이가 다르면 s2가 짧아서 들키지 않은 채 `YES`가 나올 수 있는데, 이 문제는 "길이가 같은 두 단어"를 입력으로 못박고 있어 문제가 되지 않는다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| 1. 배열 두 개(`'z'-'A'+1`칸) | `x - 'A'`로 접근, 통째로 비교 | O(L) | 정답, 빈 칸이 섞여 있음 |
| 2. 해시맵 두 개 | 분포를 각각 세고 `equals`로 비교 | O(L) | 정답, 공간 두 배, 조기 종료 없음 |
| **3. 해시맵 하나 + 차감 (채택)** | 재고에서 바로 꺼내 쓰듯 차감 | O(L) | 정답, 공간 절반, 조기 종료 |

**채택: 시도 3.** 세 시도의 시간 복잡도는 같지만, 맵을 하나만 쓰고 불일치를 만나면 바로 끝내는 시도 3이 가장 적은 공간과 가장 적은 비교로 같은 답을 낸다.

- 두 분포가 같은지 확인할 때, 양쪽을 각각 만들어 통째로 비교하기보다 한쪽을 "재고"로 두고 다른 쪽에서 **차감해 나가며** 바닥나는지 보면 맵 하나로 끝낼 수 있다.
- "길이가 같다" 같은 입력 조건은 코드 밖에서 보장되는 전제다. 이 전제가 사라지면 차감만으로는 부족하고, 다 쓰고 난 뒤 "재고가 정확히 0인가"까지 확인해야 한다.
