## 문제

하루에 운동을 했으면 1, 쉬었으면 0으로 기록한 N일간의 기록이 있다. 이 중 **최대 k번까지 "쉰 날(0)"을 "운동한 날(1)"로 바꿔 쓸 수 있을 때**, 만들 수 있는 가장 긴 연속 운동 기간의 길이를 구한다.

- 5 ≤ N < 100,000
- 입력: 첫 줄에 N과 k. 둘째 줄에 N개의 0 또는 1
- 출력: 바꿔 쓸 수 있는 조건 안에서 만들 수 있는 가장 긴 연속 1 구간의 길이

```
입력                                      출력
12 1                                      6
1 0 1 1 0 1 1 1 0 0 1 1
```

셋째 날부터 여덟째 날까지(1, 1, 0, 1, 1, 1 — 다섯째 날의 0 하나만 1로 바꾸면)가 길이 6인 연속 구간이 된다. 아홉째, 열째 날처럼 0이 두 번 연달아 나오는 구간은 k=1로는 둘 다 바꿀 수 없어 이보다 길게 만들 수 없다.

> 출처: 인프런 [자바(Java) 알고리즘 문제풀이 입문: 코딩테스트 대비](https://www.inflearn.com/course/자바-알고리즘-문제풀이-코테대비)의 [1133번 문제](https://oj.inflearn.com/problem/1133)를 소재와 예제만 바꿔 재구성했다.

## 공통 코드

아래 시도들은 입력을 읽고 결과를 출력하는 부분을 공유한다. 각 시도에서는 최장 길이를 구하는 `maxLength` 메서드만 다르다.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        int k = sc.nextInt();
        int[] arr = new int[n];
        for (int i = 0; i < n; i++) arr[i] = sc.nextInt();

        System.out.println(maxLength(k, arr)); // 로직은 각 시도 참고
    }
}
```

## 시도 1 — "바꾸는 비용"을 함수로 추출

### 접근

칸마다 "1로 바꾸는 데 드는 비용"을 함수로 뽑아냈다. 이미 1이면 비용 0, 0이면 비용 1이다. 오른쪽 끝을 넓히며 비용을 누적하다가, 누적 비용이 k를 넘으면 왼쪽 끝을 좁혀 비용을 돌려받는다.

```java
public static int maxLength(int k, int[] arr) {
    int answer = 0, lt = 0, cost = 0;
    for (int rt = 0; rt < arr.length; rt++) {
        cost += change(arr[rt]);
        while (cost > k) {
            cost -= change(arr[lt++]);
        }
        answer = Math.max(answer, rt - lt + 1);
    }
    return answer;
}

public static int change(int a) {
    return a == 0 ? 1 : 0;
}
```

### 결과

**성공** — 예제에서 `6` 출력.

복잡도: 시간 O(N), 공간 O(1). `lt`, `rt` 모두 앞으로만 움직이고 되돌아가지 않는다.

### 분석

`change()`는 "이 칸을 1로 바꾸는 데 드는 비용"을 일반화해서 표현한 함수다. 그런데 이 문제의 값은 0과 1 둘뿐이라, 함수 호출을 거치지 않고도 `arr[rt] == 0`이라는 조건 하나로 바로 알 수 있다. 값의 종류가 두 가지뿐인데 그 판단을 별도 함수로 뽑아낸 건 과한 간접화다.

## 시도 2 — 0인지를 직접 비교 (채택)

### 접근

`change()` 없이, 0을 만났을 때만 센다. 나머지는 시도 1과 똑같다 — 오른쪽을 넓히다가 0의 개수가 k를 넘으면 왼쪽을 좁힌다.

```java
public static int maxLength(int k, int[] arr) {
    int answer = 0, lt = 0, cnt = 0;
    for (int rt = 0; rt < arr.length; rt++) {
        if (arr[rt] == 0) cnt++;
        while (cnt > k) {
            if (arr[lt] == 0) cnt--;
            lt++;
        }
        answer = Math.max(answer, rt - lt + 1);
    }
    return answer;
}
```

### 결과

**성공** — 예제에서 동일하게 `6` 출력.

복잡도: 시간 O(N), 공간 O(1). 시도 1과 같다 — 함수 호출이 조건식으로 바뀌었을 뿐, 원소를 보는 횟수는 그대로다.

### 분석

시도 1의 `change()`는 "0이나 1이 아닌 다른 값도 올 수 있다"는 가능성까지 대비한 함수인데, 이 문제의 배열에는 정확히 0과 1만 들어온다. 값이 두 가지뿐일 때는 그 판단을 함수로 감싸기보다 `if (arr[rt] == 0)`처럼 바로 묻는 쪽이 더 짧다. 읽는 사람이 `change()`가 뭘 하는지 찾아보러 갈 필요도 없다. 일반화는 실제로 값의 종류가 늘어날 가능성이 있을 때 비용을 치를 만하다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| 1. 비용 함수로 추출 | `change()`로 변경 비용을 일반화 | O(N) | 정답, 불필요한 간접화 |
| **2. 0인지 직접 비교 (채택)** | `arr[rt] == 0` 조건으로 바로 확인 | O(N) | 정답, 더 짧고 직접적 |

**채택: 시도 2.** 두 시도의 복잡도는 같지만, 값이 0과 1 두 가지뿐인 이 문제에서는 함수로 감쌀 이유가 없어 시도 2가 더 단순하다.

- 입력 값의 종류가 두세 가지로 뻔하다면, 그 판단을 함수로 감싸기보다 조건식 하나로 바로 묻는 게 더 짧고 바로 읽힌다. 일반화는 실제로 값의 종류가 늘어날 가능성이 있을 때 비용을 치를 만하다.
- 0의 개수가 k를 넘을 때만 왼쪽을 좁히는 구조는 [연속 저축액 합이 M인 경우의 수](/lab/engineering/algorithm/savings-streak-sum/)의 "넓히다가 넘치면 좁히는" 틀과 같다. 세는 대상이 "합"에서 "0의 개수"로 바뀌었을 뿐이다.
