## 문제

도서관 서가에는 책을 두께가 얇은 것부터 순서대로 꽂아 둔다. 그런데 사서가 책 두 권을 실수로 자리를 맞바꿔 꽂았다(두꺼운 책 하나가 원래보다 앞쪽에, 그 책과 자리를 바꾼 더 얇은 책이 원래보다 뒤쪽에 꽂혔다). 이 사실을 모르는 신입 사서가 지금 꽂혀 있는 순서대로 책마다 1번부터 번호표를 붙였다.

책장에 꽂힌 순서대로 책의 두께가 주어질 때, 자리가 바뀐 두 책의 번호표를 순서대로(더 두꺼운 책의 번호 → 그 책과 자리를 바꾼 더 얇은 책의 번호) 출력한다.

- 책 수 N(5 ≤ N ≤ 100)
- 책 두께 H(120 ≤ H ≤ 180)인 자연수. 두께가 같은 책이 있을 수 있다.
- 입력: 첫 줄에 N, 둘째 줄에 꽂힌 순서대로 N권의 두께
- 출력: 두꺼운 책의 번호, 그 책과 자리를 바꾼 얇은 책의 번호(순서대로)

```
입력
9
121 126 151 136 141 146 146 131 161

출력
3 8
```

두께를 오름차순으로 다시 정렬하면 `121 126 131 136 141 146 146 151 161`인데, 지금 꽂힌 순서(`121 126 151 136 141 146 146 131 161`)와 비교하면 3번째(151 vs 131)와 8번째(131 vs 151) 자리만 다르다. 3번째에 꽂힌 151이 원래 8번째 자리에 있어야 할 두꺼운 책이고, 8번째에 꽂힌 131이 원래 3번째 자리에 있어야 할 얇은 책이다.

## 공통 코드

아래 시도들은 입력을 읽고 결과를 출력하는 부분을 공유한다. 각 시도에서는 자리가 바뀐 두 책을 찾는 `findSwapped` 메서드만 다르다.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        int[] thickness = new int[n];
        for (int i = 0; i < n; i++) thickness[i] = sc.nextInt();

        int[] swapped = findSwapped(thickness); // 로직은 각 시도 참고
        System.out.println(swapped[0] + " " + swapped[1]);
    }
}
```

## 시도 1 — 어긋난 자리를 훑으며 번호 기록하기 (실패)

### 접근

꽂힌 순서를 앞에서부터 보면서, 바로 앞 칸보다 두께가 더 큰(다음 칸이 더 얇아 순서가 어긋난) 지점을 찾는다. 그런 지점을 찾을 때마다 번호를 기록해 나간다.

```java
public static int[] findSwapped(int[] thickness) {
    int[] answer = new int[2];
    int idx = 0;
    for (int i = 0; i < thickness.length - 1; i++) {
        if (thickness[i] > thickness[i + 1]) {
            answer[idx] = i + idx + 1;
            idx++;
        }
    }
    return answer;
}
```

### 결과

**실패** — 주어진 예제에서는 `3 8`을 출력해 맞는 것처럼 보인다. 하지만 자리가 바뀐 두 책이 **바로 옆자리**일 때는 틀린다. 예를 들어 두께가 `122 128 154 144 162`로 꽂혀 있다면(세 번째 154와 네 번째 144가 자리를 바꾼 상황), 정답은 `3 4`여야 하는데 이 코드는 `3 0`을 출력한다.

### 분석

이 코드는 어긋난 지점을 찾을 때마다 `answer[idx] = i + idx + 1`이라는 식으로 번호를 적어 넣는다. `idx`를 더해주는 이유는, 두 책이 떨어져 꽂혀 있을 때 두 번째로 찾은 어긋난 지점(`i`)이 실제 얇은 책의 자리(`i+2`번)보다 한 칸 앞에서 발견되기 때문이다 — 그 한 칸 차이를 `idx`(이미 1이 된 상태)로 메꾼다.

문제는 두 책이 **바로 옆자리**에서 자리를 바꿨을 때다. 이때는 어긋난 지점이 **단 한 곳**만 생긴다(두꺼운 책과 얇은 책이 바로 붙어 있어서, 그 사이 한 번만 "두께가 줄어드는" 지점이 나온다). 그러면 `idx`가 0에서 1로 딱 한 번만 올라가고, `answer[1]`(두 번째 번호를 적어야 할 자리)은 끝내 채워지지 않아 기본값 0으로 남는다. "어긋난 지점의 개수로 두 책 사이의 거리를 추측한다"는 접근 자체가, 두 책이 붙어 있는 경우를 생각하지 못한 것이다.

## 시도 2 — 정렬한 배열과 비교하기 (성공, 채택)

### 접근

지금 꽂혀 있는 순서를 복사해 두께 오름차순으로 정렬한다. "원래 있어야 할 순서"인 이 정렬된 배열과, 실제로 꽂힌 순서를 처음부터 끝까지 한 칸씩 비교해서 값이 다른 자리를 찾는다.

```java
import java.util.Arrays;

public static int[] findSwapped(int[] thickness) {
    int[] sorted = thickness.clone();
    Arrays.sort(sorted);

    int[] answer = new int[2];
    int idx = 0;
    for (int i = 0; i < thickness.length; i++) {
        if (thickness[i] != sorted[i]) {
            answer[idx] = i + 1;
            idx++;
        }
    }
    return answer;
}
```

### 결과

**성공** — 예제에서 `3 8` 출력. 시도 1이 틀렸던 "바로 옆자리" 경우(`122 128 154 144 162`)에서도 `3 4`를 정확히 출력한다.

복잡도: 시간 O(N log N)(정렬이 가장 오래 걸린다), 공간 O(N)(정렬된 복사본).

### 분석

자리가 바뀐 두 책만 원래 있어야 할 자리(정렬했을 때의 자리)와 다르고, 나머지는 전부 제자리에 있다 — 두 책이 서로 붙어 있든 멀리 떨어져 있든 상관없이 항상 그렇다. 그래서 "정렬된 배열과 다른 자리가 어디인지"를 그대로 찾으면, 두 책 사이의 거리를 따로 신경 쓸 필요가 없다. 어긋난 자리 중 **먼저 나오는 쪽(인덱스가 더 작은 쪽)이 항상 두꺼운 책이다** — 원래 정렬 순서에서 두꺼운 책은 더 뒤쪽 자리를 차지해야 하는데, 그 자리를 얇은 책에게 내주고 앞자리로 왔기 때문이다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| 1. 어긋난 지점 수로 거리 추측 | 어긋난 지점마다 `idx`로 위치 보정 | - | 바로 옆자리 교환에서 실패 |
| **2. 정렬된 배열과 비교 (채택)** | 정렬 결과와 다른 자리를 그대로 찾기 | O(N log N) | 정답 |

**채택: 시도 2.** "원래 있어야 할 자리"를 정렬로 직접 구해 비교하면 두 책이 떨어져 있든 붙어 있든 똑같이 맞는다. N이 최대 100이라 정렬 비용도 전혀 문제되지 않는다.

- "어긋난 지점이 몇 개 나오는가"로 거리를 역산하는 방식은, 그 개수가 상황에 따라 달라질 수 있다는 걸 놓치기 쉽다(이 문제에서는 두 자리가 붙어 있으면 어긋난 지점이 하나만 나온다). 개수에 의존하는 보정식보다, "원래 있어야 할 상태"를 직접 구해 비교하는 쪽이 더 안전하다.
- 무언가의 "제자리"를 판단해야 할 때, 그 기준이 되는 상태(여기서는 정렬된 배열)를 실제로 만들어서 그대로 대조하면 복잡한 경우의 수를 나누지 않아도 된다.
