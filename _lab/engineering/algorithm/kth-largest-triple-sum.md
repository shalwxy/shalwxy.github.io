## 문제

추첨함에 1부터 100 사이의 번호가 적힌 공 N개가 들어 있다. 같은 번호가 적힌 공이 여러 개 있을 수 있다. 이 중 **서로 다른 공 3개**를 뽑아 번호의 합을 구하는 모든 경우를 기록한다. 기록한 값 중(**중복된 합은 한 번만 센다**) K번째로 큰 값을 구한다. 그런 값이 없으면 -1을 출력한다.

- 3 ≤ N ≤ 100, 1 ≤ K ≤ 50
- 각 공의 번호는 1 이상 100 이하의 자연수
- 입력: 첫 줄에 N과 K. 둘째 줄에 N개의 공 번호
- 출력: K번째로 큰 합(없으면 -1)

```
입력                                  출력
9 8                                   80
7 19 28 5 40 12 33 21 9
```

합을 큰 값부터 나열하면 `101, 94, 92, 89, 87, 85, 82, 80, 80, 80, 80, 78, ...`처럼 80이 네 번 겹쳐 나온다. 중복을 한 번으로만 세면 101(1번째), 94(2번째), 92(3번째), 89(4번째), 87(5번째), 85(6번째), 82(7번째), 80(8번째)가 되어, 8번째로 큰 값은 80이다.

> 출처: 인프런 [자바(Java) 알고리즘 문제풀이 입문: 코딩테스트 대비](https://www.inflearn.com/course/자바-알고리즘-문제풀이-코테대비)의 [1143번 문제](https://oj.inflearn.com/problem/1143)를 소재와 예제만 바꿔 재구성했다.

## 공통 코드

아래 시도들은 입력을 읽고 결과를 출력하는 부분을 공유한다. 각 시도에서는 K번째로 큰 합을 구하는 `kthLargestSum` 메서드만 다르다.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        int k = sc.nextInt();
        int[] arr = new int[n];
        for (int i = 0; i < n; i++) arr[i] = sc.nextInt();

        System.out.println(kthLargestSum(k, arr)); // 로직은 각 시도 참고
    }
}
```

## 시도 1 — 인덱스 세 겹으로 뽑고, 집합 끝에서 K번째 (채택)

### 접근

서로 다른 공 3개를 뽑는 모든 경우를 **인덱스** `i < j < l`로 돌며 합을 구한다. 값이 아니라 인덱스를 기준으로 삼아야, 같은 공을 두 번 이상 뽑는 경우가 생기지 않는다. 합을 `TreeSet`에 넣으면 중복된 합은 자동으로 한 번만 남고, 오름차순으로 정렬된 채 유지된다. 배열로 바꿔 끝에서 K번째를 바로 집으면 그게 "K번째로 큰 값"이다.

```java
import java.util.TreeSet;

public static int kthLargestSum(int k, int[] arr) {
    TreeSet<Integer> set = new TreeSet<>();
    for (int i = 0; i < arr.length; i++) {
        for (int j = i + 1; j < arr.length; j++) {
            for (int l = j + 1; l < arr.length; l++) {
                set.add(arr[i] + arr[j] + arr[l]);
            }
        }
    }
    if (set.size() < k) return -1;

    Integer[] sums = set.toArray(new Integer[0]);
    return sums[sums.length - k];
}
```

### 결과

**성공** — 예제에서 `80` 출력.

복잡도: 시간 O(N³)(조합 C(N,3)개를 만들어 집합에 넣는 비용이 지배), 공간은 집합에 쌓이는 distinct 합의 개수만큼인데, 공 번호가 1~100이라 합은 3~300 사이, 많아야 298가지뿐이라 N이 커져도 일정 범위 안에 머문다. N이 최대 100이라 조합은 최대 161,700개 정도라 충분히 빠르다.

### 분석

두 가지를 지켜야 한다. 첫째, 세 수를 "값"이 아니라 "인덱스" `i<j<l`로 골라야 같은 공을 중복해서 뽑는 경우가 생기지 않는다(같은 숫자가 적힌 공이 여러 개 있는 건 괜찮지만, 같은 공 한 개를 두 번 뽑는 건 안 된다). 둘째, 집합은 기본적으로 오름차순으로 정렬돼 있으니 "K번째로 큰 값"을 구하려면 **끝에서부터** 세어야 한다. `sums[sums.length - k]`는 정렬된 배열의 맨 끝(가장 큰 값, 1번째로 큰 값)에서 `k - 1`칸 앞으로 간 자리를 가리킨다.

## 다른 방법 — 합의 범위를 배열로 표시

공의 번호가 1~100으로 정해져 있으니, 세 공의 합은 3부터 300 사이로 좁혀진다. 이렇게 **합이 나올 수 있는 범위가 좁고 미리 정해져 있다면**, `TreeSet` 대신 그 범위만큼의 `boolean` 배열에 "이 합이 나온 적 있는가"만 표시해도 된다.

```java
public static int kthLargestSum(int k, int[] arr) {
    boolean[] seen = new boolean[301];
    for (int i = 0; i < arr.length; i++) {
        for (int j = i + 1; j < arr.length; j++) {
            for (int l = j + 1; l < arr.length; l++) {
                seen[arr[i] + arr[j] + arr[l]] = true;
            }
        }
    }

    int cnt = 0;
    for (int sum = 300; sum >= 3; sum--) {
        if (seen[sum]) {
            cnt++;
            if (cnt == k) return sum;
        }
    }
    return -1;
}
```

합을 만드는 삼중 루프는 그대로지만, 그 합을 "담아두는 곳"이 집합이 아니라 고정 크기 배열이라 기록이 O(1)이고 박싱(`Integer`)도 없다. 끝에서부터 훑는 것도 배열 인덱스를 거꾸로 도는 것뿐이라 `toArray` 같은 변환이 필요 없다. 어차피 담기는 값의 종류가 최대 298가지뿐이라 시도 1과 복잡도 차수 자체는 다르지 않지만, 범용 자료구조 대신 딱 맞는 크기의 배열을 쓴 만큼 더 가볍다. 다만 합의 범위를 미리 알고 있어야(1~100짜리 공 3개라는 조건에서 나온 3~300) 배열 크기를 정할 수 있다 — 번호의 범위가 미리 정해져 있지 않다면 이 방법은 쓸 수 없다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| **1. TreeSet + 끝에서 K번째 (채택)** | 인덱스로 조합, 집합이 중복 제거와 정렬을 함께 처리 | O(N³) | 정답 |
| 다른 방법. 합 범위를 배열로 | 고정 범위를 배열에 표시 | O(N³) | 정답, 합의 범위를 알아야 함 |

**채택: 시도 1.** `TreeSet`이 중복 제거와 정렬을 한꺼번에 해줘서, 합의 범위를 몰라도 되고 코드도 가장 짧다.

- "서로 다른 것 3개를 뽑는다"는 조건은 **인덱스**로 표현해야 한다. 값이 아니라 인덱스를 기준으로 `i<j<l`처럼 돌려야, 같은 원소를 두 번 쓰는 경우가 끼어들지 않는다.
- 정렬된 자료구조에서 "K번째로 작은 값"과 "K번째로 큰 값"은 방향이 반대다. 오름차순으로 쌓여 있다면, 큰 값부터 세려면 **끝에서부터** 세어야 한다.
- 담아야 할 값의 범위가 좁고 미리 알려져 있다면, 범용 자료구조(`TreeSet`) 대신 그 범위만큼의 배열로 바꿔 더 가볍게 처리할 수 있다.
