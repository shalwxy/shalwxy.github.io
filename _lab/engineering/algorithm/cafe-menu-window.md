## 문제

카페에서 N시간 동안, 한 시간마다 그 시간에 가장 많이 팔린 메뉴의 번호를 기록했다. 이 기록에서 **연속된 K시간 구간마다**, 그 구간에 적힌 메뉴 번호가 몇 종류인지(같은 번호가 여러 번 적혀 있으면 한 종류로 센다) 첫 구간부터 순서대로 구한다.

- 5 ≤ N ≤ 100,000, 2 ≤ K ≤ N
- 각 시간의 메뉴 번호는 500 이하의 음이 아닌 정수
- 입력: 첫 줄에 N과 K. 둘째 줄에 N개의 메뉴 번호
- 출력: 각 구간에 적힌 메뉴 번호의 종류 수를 순서대로

```
입력                               출력
8 3                                2 3 2 2 3 3
5 8 5 3 3 9 8 3
```

첫 구간(1~3시)에 적힌 번호는 5, 8, 5로, 같은 5가 두 번 적혀 있어 서로 다른 번호는 5와 8 두 종류다. 둘째 구간(2~4시)은 8, 5, 3으로 세 종류, 셋째 구간(3~5시)은 5, 3, 3으로 두 종류다. 이렇게 한 시간씩 옮기며 구간마다 종류 수를 구하면 `2 3 2 2 3 3`.

> 출처: 인프런 [자바(Java) 알고리즘 문제풀이 입문: 코딩테스트 대비](https://www.inflearn.com/course/자바-알고리즘-문제풀이-코테대비)의 [1141번 문제](https://oj.inflearn.com/problem/1141)를 소재와 예제만 바꿔 재구성했다.

## 공통 코드

아래 시도들은 입력을 읽고 결과를 출력하는 부분을 공유한다. 각 시도에서는 구간별 종류 수를 구하는 `countTypes` 메서드만 다르다.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        int k = sc.nextInt();
        int[] arr = new int[n];
        for (int i = 0; i < n; i++) arr[i] = sc.nextInt();

        int[] answer = countTypes(k, arr); // 로직은 각 시도 참고
        for (int x : answer) System.out.print(x + " ");
    }
}
```

## 시도 1 — 구간마다 새 해시맵

### 접근

구간이 한 칸 옮길 때마다, 그 구간의 K개 원소를 처음부터 다시 세는 해시맵을 새로 만든다. 맵에 쌓인 키의 개수(`map.size()`)가 곧 그 구간의 종류 수다.

```java
import java.util.HashMap;
import java.util.Map;

public static int[] countTypes(int k, int[] arr) {
    int[] answer = new int[arr.length - k + 1];
    int lt = 0;
    for (int rt = k - 1; rt < arr.length; rt++) {
        Map<Integer, Integer> map = new HashMap<>();
        for (int j = lt; j <= rt; j++) {
            map.put(arr[j], map.getOrDefault(arr[j], 0) + 1);
        }
        answer[lt++] = map.size();
    }
    return answer;
}
```

### 결과

**성공** — 예제에서 `2 3 2 2 3 3` 출력.

복잡도: 시간 O(N×K), 공간 O(K)(구간마다 새 맵). N이 최대 100,000이고 K도 최대 N까지 가능해서, N×K는 K가 N의 절반 정도일 때 최악 N²/4 ≈ 25억에 이른다. 1,500ms 제한 안에 끝난다고 보장할 수 없다 — 예제처럼 작은 입력에서는 드러나지 않는다.

### 분석

구간이 한 칸 옮길 때마다, 바로 앞 구간과 겹치는 K−1개의 원소까지 전부 새 맵에 다시 넣는다. [연속 K일 최대 대출 권수](/lab/engineering/algorithm/library-loan-window/)에서 합을 구할 때와 똑같이, 겹치는 부분을 재사용하면 매번 K개를 통째로 다시 넣을 필요가 없을 것 같다.

## 시도 2 — 해시맵 하나를 들고 다니며 넣고 빼기 (채택)

### 접근

해시맵 하나로 구간을 유지한다. 처음 K−1개는 미리 넣어두고, 구간을 한 칸씩 오른쪽으로 옮길 때마다 새로 들어오는 원소 하나를 넣어 종류 수를 기록한 다음, 빠지는 원소 하나를 빼서 다음 구간을 준비한다. 빠지는 원소의 개수가 0이 되면 **키 자체를 지운다** — 그래야 `map.size()`가 "지금 구간에 실제로 있는 종류"만 센다.

여기서 K개(이 문제의 예시에서는 3개)를 처음부터 다 채워두지 않고 K−1개(2개)만 채워두는 이유가 있다. K개를 다 채우면 첫 구간은 반복문에 들어가기도 전에 이미 완성돼 있다. 그 첫 구간의 종류 수를 기록하려면 반복문 밖에서 한 번 더 기록해주거나, 반복문 안에서 "첫 바퀴만 넣지 않고 기록만 한다"는 예외를 둬야 한다. K−1개만 채워두면, 반복문의 모든 바퀴가 "하나 넣어서 구간을 완성 → 종류 수 기록 → 맨 앞 하나 빼기"를 예외 없이 똑같이 반복한다.

```java
public static int[] countTypes(int k, int[] arr) {
    int[] answer = new int[arr.length - k + 1];
    Map<Integer, Integer> map = new HashMap<>();
    for (int i = 0; i < k - 1; i++) {
        map.put(arr[i], map.getOrDefault(arr[i], 0) + 1);
    }

    int lt = 0;
    for (int rt = k - 1; rt < arr.length; rt++) {
        map.put(arr[rt], map.getOrDefault(arr[rt], 0) + 1);
        answer[lt] = map.size();

        map.put(arr[lt], map.get(arr[lt]) - 1);
        if (map.get(arr[lt]) == 0) map.remove(arr[lt]);
        lt++;
    }
    return answer;
}
```

### 결과

**성공** — 예제에서 동일하게 `2 3 2 2 3 3` 출력.

복잡도: 시간 O(N), 공간 O(K)(맵에 들어갈 수 있는 키는 최대 K개). 원소마다 맵에 들어가고 나가는 횟수가 각각 한 번뿐이라, N이 커져도 선형으로 끝난다.

### 분석

시도 1은 구간이 겹치는데도 매번 새 맵을 만들어 K개를 전부 다시 넣었다. 시도 2는 맵 하나를 들고 다니면서, 구간을 옮길 때 "새로 들어오는 원소 하나만 넣고, 빠지는 원소 하나만 빼는" 두 번의 연산으로 다음 구간을 완성한다. 종류 수도 `map.size()`로 그 자리에서 바로 얻어지니, 맵을 처음부터 순회해 세는 과정조차 필요 없다.

빠지는 원소를 뺄 때 개수를 0으로 낮추는 것만으로는 부족하다. 키를 지우지 않으면 `map.size()`가 "지금까지 한 번이라도 들어온 적 있는 종류"까지 세어버려서, 이미 구간에서 빠져나간 메뉴도 계속 종류 수에 포함된다. `if (map.get(arr[lt]) == 0) map.remove(arr[lt]);`가 이 방법의 핵심이다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| 1. 구간마다 새 맵 | 매번 K개를 새로 넣어 센다 | O(N×K) | 정답, 큰 입력에서 시간 초과 우려 |
| **2. 맵 하나로 넣고 빼기 (채택)** | 겹치는 구간은 유지, 양 끝만 갱신 | O(N) | 정답, 선형 시간 |

**채택: 시도 2.** 제약(N ≤ 100,000)에서 시도 1의 N×K는 최악 N²/4까지 늘어나 시간 제한이 불안하지만, 시도 2는 원소마다 한 번씩만 넣고 빼 안전하게 통과한다.

- 슬라이딩 윈도우에서 "구간 안의 종류 수(혹은 합, 개수)"를 셀 때, 자료구조를 매번 새로 만들지 않고 **양 끝의 변화만 반영**하면 겹치는 부분을 다시 셀 필요가 없다. [연속 저축액 합이 M인 경우의 수](/lab/engineering/algorithm/savings-streak-sum/)에서 합을 다루던 것과 같은 틀이다.
- 해시맵으로 "현재 구간에 들어있는 종류"를 센다면, 빠지는 값의 개수가 0이 될 때 **키 자체를 지워야** 한다. 지우지 않으면 `map.size()`가 "지금 구간에 있는 종류"가 아니라 "한 번이라도 들어온 적 있는 종류"를 세게 된다.
