## 문제

여행지에 들를 수 있는 장소마다 영문 대문자 코드가 붙어 있다. 그중 일부는 **필수 코스**이고, 필수 코스는 정해진 순서대로 들러야 한다. 예를 들어 필수 코스 순서가 D, F, B라면 D를 들른 뒤에 F를, F를 들른 뒤에 B를 들러야 한다(필수 코스가 아닌 곳은 동선 중 아무 때나 들러도 된다).

필수 코스의 순서와 여행자가 실제로 짠 동선이 주어질 때, 그 동선이 필수 코스 순서를 지키고 있는지 판별한다. 동선에 있는 장소는 그 순서대로 전부 들른다고 가정한다.

- 모든 장소는 영문 대문자 한 글자로 나타낸다
- 동선의 길이는 30 이하
- 입력: 첫 줄에 필수 코스 순서, 둘째 줄에 여행자가 짠 동선
- 출력: 순서를 지켰으면 `YES`, 아니면 `NO`

```
입력
DFB
ADFGCBE

출력
YES
```

동선 `ADFGCBE`에서 필수 코스만 순서대로 뽑으면 D, F, B가 되어 필수 코스 순서와 정확히 같다. 만약 동선이 `ADBGCFE`처럼 B를 F보다 먼저 들렀다면, 필수 코스 순서가 D, B, F가 되어버려 `NO`였을 것이다.

## 공통 코드

아래 시도들은 입력을 읽고 결과를 출력하는 부분을 공유한다. 각 시도에서는 순서를 확인하는 `isValidOrder` 메서드만 다르다.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String required = sc.next();
        String plan = sc.next();

        System.out.println(isValidOrder(required, plan)); // 로직은 각 시도 참고
    }
}
```

## 시도 1 — 필수 코스가 아닌 글자를 걸러내기 (채택)

### 접근

동선 문자열에서 필수 코스가 아닌 글자를 전부 지우면, 남는 글자들이 "동선에서 필수 코스가 나온 순서"가 된다. 이걸 필수 코스 순서와 그대로 비교하면 된다. 어떤 글자를 지울지는 정규식 문자 클래스(`[^...]`)로 표현하는데, 이 클래스를 고정된 알파벳이 아니라 **입력으로 받은 `required` 문자열 그대로** 만든다.

```java
public static String isValidOrder(String required, String plan) {
    String filtered = plan.replaceAll(String.format("[^%s]", required), "");
    return required.equals(filtered) ? "YES" : "NO";
}
```

### 결과

**성공** — 예제에서 `YES` 출력.

복잡도: 시간 O(L₁+L₂)(L₁은 필수 코스 수, L₂는 동선의 길이), 공간 O(L₂).

### 분석

`String.format("[^%s]", required)`는 `required`가 `"DFB"`이면 정규식 `"[^DFB]"`를 만든다 — "D, F, B가 아닌 글자는 전부 지운다"는 뜻이다. 필수 코스가 달라지면 이 정규식도 그 자리에서 같이 바뀐다.

여기서 중요한 건 **지울 대상을 코드에 직접 적지 않고, 입력값(`required`)에서 그대로 만들어낸다**는 점이다. 만약 "D, F, B" 같은 특정 알파벳을 정규식에 직접 박아 넣었다면, 필수 코스가 다른 글자들로 바뀌는 순간 완전히 틀린 답을 낸다 — 이번 예제에서는 우연히 맞아도, 필수 코스가 "XYZ"라면 그 고정된 패턴은 아무것도 걸러내지 못한다. `required`를 그대로 정규식에 끼워 넣으면 필수 코스가 무엇이든 항상 맞는 문자 클래스가 만들어진다.

## 다른 방법 — 큐에서 순서대로 하나씩 확인

필터링 후 통째로 비교하는 대신, 필수 코스 순서를 큐에 넣어두고 동선을 한 글자씩 보면서 그 자리에서 바로 확인할 수도 있다. 지금 본 글자가 **아직 큐에 남아있는 필수 코스면** 큐에서 하나를 꺼내 비교하고, 꺼낸 값이 다르면 그 즉시 `NO`로 끝낸다.

```java
import java.util.LinkedList;
import java.util.Queue;

public static String isValidOrder(String required, String plan) {
    Queue<Character> queue = new LinkedList<>();
    for (char c : required.toCharArray()) queue.offer(c);

    for (char c : plan.toCharArray()) {
        if (queue.contains(c)) {
            if (c != queue.poll()) return "NO";
        }
    }
    return queue.isEmpty() ? "YES" : "NO";
}
```

복잡도는 시간 O(L₁×L₂)(동선의 글자마다 큐 안을 훑어 `contains`를 확인한다), 공간 O(L₁) — 시도 1보다 차수가 높다. 그 대신 순서가 어긋나는 순간 바로 멈춘다는 장점이 있다. 시도 1은 끝까지 다 걸러낸 뒤에야 비교하지만, 이 방법은 동선을 보는 도중에 이미 틀렸다는 걸 알면 더 볼 필요가 없다.

동선이 아주 길고 순서가 앞부분에서 이미 틀린 경우가 잦다면 이 조기 종료가 유리하고, 그렇지 않다면 시도 1의 한 줄짜리 필터링이 더 단순하다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| **1. 정규식으로 필터링 (채택)** | `required`로 문자 클래스를 직접 만듦 | O(L₁+L₂) | 정답 |
| 다른 방법. 큐로 순서 확인 | 필요한 글자만 꺼내 즉시 비교 | O(L₁×L₂) | 정답, 틀리면 즉시 종료 |

**채택: 시도 1.** 지울 대상을 입력에서 그대로 가져와 일반적으로 동작하고, 코드도 한 줄로 가장 단순하다.

- "이번 예제에서 걸러야 할 건 A, B, C"처럼 **입력값을 코드에 직접 박아 넣으면**, 그 입력이 조금만 달라져도 틀린 답을 낸다. 걸러내는 기준은 항상 주어진 입력에서 가져와야 한다.
- 어떤 문자열이 다른 문자열의 부분열(순서를 유지한 채 골라낸 글자들)인지 확인할 때, "해당 글자만 걸러서 통째로 비교하는" 방식과 "필요한 글자만 큐에 담아두고 하나씩 맞춰보는" 방식 둘 다 쓸 수 있다. 코드를 단순하게 두고 싶으면 전자, 틀린 걸 빨리 알아채야 하면 후자가 낫다.
