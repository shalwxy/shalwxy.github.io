## 문제

조직도에서 "말단 사원"은 더 이상 부하가 없는 사람을 뜻한다. 최상위(1번)에서 가장 가까운 말단 사원까지 가는 데 걸리는 최소 단계 수(거쳐야 하는 보고 라인의 수, 즉 간선의 개수)를 구한다.

이 조직도에서 가장 가까운 말단 사원은 3번이고, 최상위(1번)에서 3번까지 가는 데 1단계가 걸린다(4번, 5번은 2단계).

이 문제는 깊이 우선 탐색(DFS)과 너비 우선 탐색(BFS) 두 가지 방식으로 모두 풀어본다 — 같은 문제를 어떻게 다르게 접근하는지 비교해본다.

> 출처: 인프런 [자바(Java) 알고리즘 문제풀이 입문: 코딩테스트 대비](https://www.inflearn.com/course/자바-알고리즘-문제풀이-코테대비)의 재귀 단원 문제를 소재만 바꿔 재구성했다.

## 공통 코드

```java
class Node {
    int val;
    Node left;
    Node right;

    Node(int val) {
        this.val = val;
    }
}

public class Main {
    public static Node root;

    public static void main(String[] args) {
        root = new Node(1);
        root.left = new Node(2);
        root.right = new Node(3);
        root.left.left = new Node(4);
        root.left.right = new Node(5);

        System.out.println(nearestLeafDepth(root)); // 로직은 각 시도 참고
    }
}
```

## 시도 1 — DFS로 양쪽을 다 내려가 더 짧은 쪽 고르기 (성공이지만 비효율)

### 접근

자식이 없으면(말단) 지금까지 내려온 깊이가 그대로 답이다. 자식이 하나뿐이면 그쪽으로, 둘 다 있으면 양쪽을 각각 끝까지 내려가 본 뒤 더 작은 깊이를 택한다.

```java
public static int nearestLeafDepth(Node root) {
    return dfs(root, 0);
}

public static int dfs(Node root, int level) {
    if (root.left == null && root.right == null) {
        return level;
    }
    if (root.left == null) {
        return dfs(root.right, level + 1);
    }
    if (root.right == null) {
        return dfs(root.left, level + 1);
    }
    return Math.min(dfs(root.left, level + 1), dfs(root.right, level + 1));
}
```

### 결과

**성공** — 주어진 조직도에서 `1`이 출력된다.

다만 양쪽 자식이 모두 있는 노드를 만나면, **왼쪽을 끝까지 다 내려가 본 뒤에야** 오른쪽을 본다 — `Math.min(dfs(left), dfs(right))`를 계산하려면 둘 다 먼저 끝까지 호출해야 하기 때문이다. 왼쪽에 아주 깊은 가지 하나와, 오른쪽에 바로 말단이 있는 트리로 실험해보면 이 차이가 분명하게 드러난다. 왼쪽 가지를 50만 단계짜리 외길로 만들고 오른쪽에 깊이 1짜리 말단 하나만 둔 트리에서, 이 DFS는 **StackOverflowError로 아예 멈춰버린다** — 답은 명백히 1(오른쪽)인데도, 그 답을 확인하기 전에 왼쪽의 50만 단계를 먼저 재귀로 내려가다가 호출 스택이 넘쳐버리기 때문이다.

### 분석

DFS는 "왼쪽을 끝까지 보고 돌아와야 오른쪽과 비교할 수 있다"는 구조라서, 답이 오른쪽의 얕은 곳에 있어도 왼쪽이 깊으면 그 깊이만큼은 무조건 다 내려가 봐야 한다. 재귀 호출이 내려가는 깊이가 곧 호출 스택이 쌓이는 깊이이므로, 트리가 한쪽으로 치우쳐 아주 깊어지면 비교해볼 필요도 없었던 가지 때문에 스택이 먼저 바닥난다.

## 시도 2 — BFS로 가장 가까운 레벨에서 먼저 찾기 (성공, 채택)

### 접근

큐에 루트를 넣고 레벨별로 넓혀간다. 자식이 없는(말단) 노드를 만나는 순간, 그 레벨이 곧 가장 가까운 말단까지의 거리다.

```java
import java.util.LinkedList;
import java.util.Queue;

public static int nearestLeafDepth(Node root) {
    Queue<Node> queue = new LinkedList<>();
    queue.offer(root);
    int level = 0;
    while (!queue.isEmpty()) {
        int size = queue.size();
        for (int i = 0; i < size; i++) {
            Node cur = queue.poll();
            if (cur.left == null && cur.right == null) {
                return level;
            }
            if (cur.left != null) queue.offer(cur.left);
            if (cur.right != null) queue.offer(cur.right);
        }
        level++;
    }
    return -1;
}
```

### 결과

**성공** — 주어진 조직도에서 `1`이 출력된다.

같은 "왼쪽은 50만 단계 외길, 오른쪽은 깊이 1짜리 말단" 트리에서도 BFS는 레벨 1에서 바로 답을 찾아 즉시 끝난다 — 왼쪽 가지를 단 한 걸음도 더 내려가 보지 않는다.

복잡도: 최악의 경우 시간 O(N), 공간 O(N)(N은 노드 수)이지만, 가장 가까운 말단이 얕은 곳에 있으면 그보다 훨씬 적게 보고 끝난다.

### 분석

BFS는 레벨 0, 레벨 1, 레벨 2, … 순서로 큐에 쌓인 걸 전부 확인하고서야 다음 레벨로 넘어간다. 그래서 "자식이 없는 노드"를 처음 만나는 순간이 곧 "가장 가까운 말단"이라고 바로 확정할 수 있다 — 아직 큐에 안 들어온, 더 깊은 레벨의 노드들은 볼 필요조차 없다. DFS처럼 한쪽 가지를 끝까지 다녀와야 비교할 수 있는 구조가 아니라서, 트리가 아무리 한쪽으로 깊게 치우쳐 있어도 얕은 쪽의 답을 찾는 데는 영향을 주지 않는다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| 1. DFS로 양쪽을 비교 | 양쪽을 끝까지 내려가 본 뒤 작은 쪽 선택 | 최악의 경우 O(N), 깊은 트리에서 스택 오버플로 위험 | 정답이지만 불안정 |
| **2. BFS로 레벨별 탐색 (채택)** | 말단을 처음 만난 레벨이 곧 답 | 최악의 경우 O(N), 답을 찾으면 즉시 종료 | 정답 |

**채택: 시도 2.** "가장 가까운 것을 찾는다"는 질문에는 가까운 것부터 보장되는 순서로 탐색하는 BFS가 자연스럽게 들어맞는다. DFS는 답과 상관없는 깊은 가지까지 전부 내려가 봐야 하고, 극단적인 경우 재귀 호출 자체가 감당이 안 될 수 있다.

- "가장 가까운 것"을 찾는 문제는 "가능한 모든 것을 끝까지 본 뒤 비교"(DFS)하기보다, "가까운 것부터 순서대로 보다가 처음 만나는 순간 멈추는"(BFS) 방식이 더 안전하다 — 답과 무관한 깊은 부분까지 낭비하지 않는다.
- 재귀(DFS)는 코드가 간결하지만, 트리나 그래프가 한쪽으로 깊게 치우칠 수 있다면 호출 스택이 감당할 수 있는지도 함께 따져봐야 한다. 큐를 쓰는 BFS는 반복문이라 이런 걱정이 없다.
