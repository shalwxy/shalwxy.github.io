## 문제

창고 선반에 상품이 뒤섞여 진열돼 있다. 재고 정리를 위해, 선반 위 상품을 가격이 낮은 순서대로 다시 줄 세운다.

- 상품 수 N(1 ≤ N ≤ 100)
- 입력: 첫 줄에 N, 둘째 줄에 선반에 놓인 순서대로 상품의 가격(정수, int 범위 안)
- 출력: 가격이 낮은 순서로 정렬한 결과

```
입력
6
32 15 47 9 21 38

출력
9 15 21 32 38 47
```

가장 싼 9가 맨 앞에, 가장 비싼 47이 맨 뒤에 오고 나머지도 가격이 낮은 순서대로 15, 21, 32, 38이 그 사이에 자리한다.

> 출처: 인프런 [자바(Java) 알고리즘 문제풀이 입문: 코딩테스트 대비](https://www.inflearn.com/course/자바-알고리즘-문제풀이-코테대비) 강의의 정렬 단원 문제를 소재와 예제만 바꿔 재구성했다.

## 공통 코드

아래 시도들은 입력을 읽고 결과를 출력하는 부분을 공유한다. 각 시도에서는 정렬하는 `sortAscending` 메서드만 다르다.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        int[] prices = new int[n];
        for (int i = 0; i < n; i++) prices[i] = sc.nextInt();

        sortAscending(prices); // 로직은 각 시도 참고

        StringBuilder sb = new StringBuilder();
        for (int price : prices) sb.append(price).append(' ');
        System.out.println(sb.toString().trim());
    }
}
```

세 알고리즘이 한 바퀴에 무슨 일을 하는지는, 상품을 조금 줄인 5개짜리 예시 `32 15 47 9 21`로 살펴본다.

## 시도 1 — 선택 정렬 (성공)

### 접근

아직 정리되지 않은 구간(i번째부터 끝까지)에서 가장 싼 상품을 찾아, 그 상품을 구간의 맨 앞(i번째 자리)과 자리를 맞바꾼다. 이 구간을 한 칸씩 좁혀가며 반복하면 앞쪽부터 가격이 낮은 순서로 확정된다.

```java
public static void sortAscending(int[] prices) {
    for (int i = 0; i < prices.length; i++) {
        int minIdx = i;
        for (int j = i + 1; j < prices.length; j++) {
            if (prices[minIdx] > prices[j]) {
                minIdx = j;
            }
        }
        swap(prices, i, minIdx);
    }
}

public static void swap(int[] prices, int i, int j) {
    int tmp = prices[i];
    prices[i] = prices[j];
    prices[j] = tmp;
}
```

### 결과

**성공** — 예제에서 `9 15 21 32 38 47` 출력.

복잡도: 시간 O(N²)(매 바퀴 남은 구간 전체를 훑어 최솟값을 찾는다), 공간 O(1).

### 분석

바깥 루프가 한 바퀴 돌 때마다 자리가 정확히 하나 확정된다. 비교 횟수는 입력이 어떤 순서로 섞여 있든 항상 같다 — 안쪽 루프가 "더 싼 값을 찾았는가"와 상관없이 구간 전체를 끝까지 훑기 때문이다. 대신 자리 교체(swap)는 바깥 루프 한 바퀴당 많아야 1번만 일어난다.

## 시도 2 — 버블 정렬 (성공)

### 접근

선반 뒤쪽부터 앞쪽으로 오면서, 바로 옆에 붙어 있는 두 상품의 가격을 비교해 왼쪽이 더 비싸면 자리를 바꾼다. 이렇게 한 바퀴를 돌면, 아직 정리되지 않은 구간에서 가장 싼 상품이 인접 교환을 거듭하며 맨 앞까지 밀려와 자리를 잡는다.

```java
public static void sortAscending(int[] prices) {
    for (int i = 0; i < prices.length - 1; i++) {
        for (int j = prices.length - 1; j > i; j--) {
            if (prices[j - 1] > prices[j]) {
                swap(prices, j - 1, j);
            }
        }
    }
}
```

`swap` 메서드는 시도 1과 같다.

### 결과

**성공** — 예제에서 `9 15 21 32 38 47` 출력.

복잡도: 시간 O(N²)(선택 정렬과 같은 횟수만큼 비교한다), 공간 O(1).

### 분석

선택 정렬과 비교 횟수는 똑같지만 자리 교체 방식이 다르다 — 선택 정렬은 최솟값을 찾은 뒤 딱 한 번만 바꾸지만, 버블 정렬은 그 값이 맨 앞까지 가는 동안 지나는 칸마다 매번 자리를 바꾼다. 그만큼 교체 횟수가 늘어날 수 있다(최악의 경우 선택 정렬보다 훨씬 많다). 또한 이 코드는 "이번 바퀴에 교체가 한 번도 없었다"는 사실을 따로 기억하지 않기 때문에, 상품이 이미 가격순으로 진열돼 있어도 매번 구간 전체를 끝까지 훑는다 — 비교 횟수가 입력 상태와 무관하다는 점은 선택 정렬과 같다.

## 시도 3 — 삽입 정렬 (성공, 채택)

### 접근

이미 가격순으로 정리된 앞부분(0번째 ~ i-1번째)에 다음 상품(i번째)을 끼워 넣는다. 끼워 넣을 자리를 찾을 때까지, 그 상품보다 비싼 값들을 한 칸씩 뒤로 밀어낸다.

```java
public static void sortAscending(int[] prices) {
    for (int i = 1; i < prices.length; i++) {
        int key = prices[i];
        int j = i;
        while (j > 0 && prices[j - 1] > key) {
            prices[j] = prices[j - 1];
            j--;
        }
        prices[j] = key;
    }
}
```

{% include figure image_path="/assets/img/lab/shelf-price-insertion-sort.svg" alt="앞쪽 세 칸은 그대로, 네 번째 칸은 비어 있고 그 위에 빨간 테두리 칸이 떠 있다. 파란 화살표 세 개가 세 칸을 오른쪽으로 한 칸씩 밀고, 빨간 화살표가 떠 있는 칸에서 맨 앞 칸으로 이어진다" caption="정렬 전(위)과 삽입 후(아래). 빨간 테두리 칸이 들어올린 값, 파란 화살표가 자리를 비켜주는 이동, 초록 테두리가 삽입된 자리다" %}

### 결과

**성공** — 예제에서 `9 15 21 32 38 47` 출력.

복잡도: 시간 O(N²)(최악의 경우), 공간 O(1). 다만 앞부분이 이미 정렬에 가까울수록 `while`문이 금방 멈춰 실제 비교 횟수가 줄어든다 — 입력이 이미 오름차순이면 각 바퀴의 `while`이 단 한 번도 돌지 않아 전체 시간이 O(N)까지 떨어진다.

### 분석

선택 정렬과 버블 정렬은 안쪽 루프가 "정해진 범위를 끝까지" 도는 반면, 삽입 정렬의 `while`문은 "더 이상 밀어낼 값이 없으면" 그 자리에서 바로 멈춘다. 이 멈추는 조건 자체가 입력의 정렬 상태에 반응하기 때문에, 코드를 더 손대지 않아도 이미 정렬된(또는 정렬에 가까운) 입력에서 저절로 빨라진다. 선택 정렬과 버블 정렬은 입력이 어떻든 비교 횟수가 고정돼 있어서 이런 이득이 없다.

## 다른 방법 — 버블 정렬에 조기 종료 추가하기

버블 정렬도 "이번 바퀴에 자리 교체가 한 번도 없었다"는 사실을 따로 기억해두면, 삽입 정렬처럼 이미 정렬된 입력에서 더 빨리 끝낼 수 있다.

```java
public static void sortAscending(int[] prices) {
    for (int i = 0; i < prices.length - 1; i++) {
        boolean swapped = false;
        for (int j = prices.length - 1; j > i; j--) {
            if (prices[j - 1] > prices[j]) {
                swap(prices, j - 1, j);
                swapped = true;
            }
        }
        if (!swapped) break;
    }
}
```

복잡도는 최악의 경우 여전히 O(N²)이지만, 입력이 이미 정렬돼 있으면 첫 바퀴에서 교체가 한 번도 안 일어나 그 자리에서 바로 멈춘다 — O(N). 다만 이건 "교체가 있었는지"를 변수 하나로 따로 챙겨야 알 수 있는 것이고, 삽입 정렬은 `while`문의 멈춤 조건 자체가 이미 그 역할을 한다. 입력이 이미 정렬에 가까울 가능성이 높다면 버블 정렬에도 이런 조기 종료를 넣는 게 좋고, 그렇지 않다면 원래 코드(시도 2)로 충분하다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| 1. 선택 정렬 | 구간 최솟값을 찾아 한 번만 교체 | O(N²), 교체 최대 N번 | 정답 |
| 2. 버블 정렬 | 인접 교환으로 최솟값을 앞까지 밀어냄 | O(N²), 교체 더 잦음 | 정답 |
| **3. 삽입 정렬 (채택)** | 정렬된 구간에 끼워 넣기, 멈출 자리를 스스로 찾음 | O(N²), 정렬에 가까우면 O(N) | 정답 |
| 다른 방법. 버블 정렬 + 조기 종료 | 교체가 없으면 그 자리에서 멈춤 | O(N²), 정렬에 가까우면 O(N) | 정답 |

**채택: 시도 3.** 세 방식 모두 최악의 경우 O(N²)로 같지만, 삽입 정렬만 코드를 더 손대지 않아도 입력이 정렬에 가까울 때 저절로 빨라진다.

- 세 정렬 모두 "확정된 구간을 한 칸씩 늘려간다"는 틀은 같다. 차이는 **그 구간에 새 값을 어떻게 끼워 넣는가**에 있다 — 통째로 찾아서 한 번에 옮기는지(선택), 이웃과 부딪히며 밀어내는지(버블), 제자리를 찾을 때까지만 밀어내는지(삽입).
- 안쪽 반복문이 "정해진 횟수"를 도는지 "멈출 조건"을 보고 스스로 도는지를 구분해보면, 그 알고리즘이 입력 상태에 반응하는지(적응적인지) 알 수 있다.
