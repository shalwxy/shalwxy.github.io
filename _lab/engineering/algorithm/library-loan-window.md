## 문제

도서관에서 N일 동안 매일 몇 권이 대출됐는지 기록했다. 이 기록에서 **연속된 K일** 동안의 대출 권수 합이 가장 큰 값을 구한다.

- 5 ≤ N ≤ 100,000, 2 ≤ K ≤ N
- 각 날짜의 대출 권수는 500 이하의 음이 아닌 정수
- 입력: 첫 줄에 N과 K. 둘째 줄에 N개의 대출 권수
- 출력: 연속된 K일의 대출 권수 합 중 최댓값

```
입력                                  출력
9 3                                   72
14 9 23 31 18 7 26 12 20
```

셋째 날부터 다섯째 날까지(23, 31, 18)의 합이 72권으로 가장 많다. 둘째 날부터 넷째 날까지(9, 23, 31)는 63권, 여섯째 날부터 여덟째 날까지(26, 12, 20)는 58권으로 그 뒤를 잇지만 72권을 넘지 못한다.

> 출처: 인프런 [자바(Java) 알고리즘 문제풀이 입문: 코딩테스트 대비](https://www.inflearn.com/course/자바-알고리즘-문제풀이-코테대비)의 [1130번 문제](https://oj.inflearn.com/problem/1130)를 소재와 예제만 바꿔 재구성했다.

## 공통 코드

아래 시도들은 입력을 읽고 결과를 출력하는 부분을 공유한다. 각 시도에서는 연속된 K개 구간의 최대 합을 구하는 `maxWindowSum` 메서드만 다르다.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        int k = sc.nextInt();
        int[] arr = new int[n];
        for (int i = 0; i < n; i++) arr[i] = sc.nextInt();

        System.out.println(maxWindowSum(k, arr)); // 로직은 각 시도 참고
    }
}
```

## 시도 1 — 창마다 처음부터 다시 합산

### 접근

시작 인덱스 `i`를 0부터 `arr.length - k`까지 옮기면서, 그 자리에서부터 K개를 처음부터 다시 더해 최댓값을 갱신했다.

```java
public static int maxWindowSum(int k, int[] arr) {
    int max = 0;
    for (int i = 0; i <= arr.length - k; i++) {
        int sum = 0;
        for (int j = i; j < i + k; j++) {
            sum += arr[j];
        }
        if (sum > max) max = sum;
    }
    return max;
}
```

### 결과

**성공** — 예제에서 `72` 출력.

복잡도: 시간 O(N×K), 공간 O(1).

N이 최대 100,000이고 K도 최대 N까지 가능해서, K가 N의 절반 정도일 때 N×K는 약 25억에 이른다. 1,000ms 제한 안에 끝난다고 보장할 수 없다 — 예제처럼 작은 입력에서는 이 문제가 드러나지 않는다.

### 분석

창을 한 칸 옮길 때마다 바로 앞 창과 겹치는 K−1개의 원소를 매번 다시 더한다. 예를 들어 `i`번째 창과 `i+1`번째 창은 원소 K−1개를 공유하는데, 그 K−1개를 두 번 다시 계산하는 셈이다. 창이 한 칸 옮길 때 "빠지는 원소 하나를 빼고 들어오는 원소 하나를 더하는 것"만으로 다음 합을 구할 수 있다면, 매번 K개를 통째로 다시 더할 필요가 없다.

## 시도 2 — 겹치는 부분을 재사용 (채택)

### 접근

첫 K개의 합을 미리 구해두고, 창을 한 칸씩 옮길 때마다 "빠지는 원소"를 빼고 "들어오는 원소"를 더해 합을 갱신했다.

```java
public static int maxWindowSum(int k, int[] arr) {
    int sum = 0;
    for (int i = 0; i < k; i++) sum += arr[i];

    int max = sum;
    for (int i = 0; i < arr.length - k; i++) {
        sum = sum - arr[i] + arr[i + k];
        if (sum > max) max = sum;
    }
    return max;
}
```

### 결과

**성공** — 예제에서 동일하게 `72` 출력.

복잡도: 시간 O(N), 공간 O(1). 원소마다 더해지고 빠지는 횟수가 각각 최대 한 번이라, N이 커져도 선형으로 끝난다.

### 분석

창이 `[i, i+k)`에서 `[i+1, i+k+1)`로 옮길 때, 두 창이 공유하는 `[i+1, i+k)` 구간은 그대로 쓸 수 있다. 달라지는 건 "빠지는 `arr[i]`"와 "들어오는 `arr[i+k]`" 둘뿐이다. 시도 1은 이 사실을 쓰지 않고 창마다 K개를 통째로 다시 더했지만, 시도 2는 이전 창의 합을 들고 다니다가 둘만 가감해 다음 창의 합을 O(1)에 구한다 — 창을 N−K+1번 옮기는 전체 과정이 O(N)으로 줄어드는 이유다.

## 다른 방법 — 프리픽스 합

구간 합을 한 번만 구하는 게 아니라 K가 여러 번 바뀌며 반복 질의된다면, 프리픽스 합 배열을 미리 만들어 두는 방법도 있다. `prefix[i]`를 `arr[0..i-1]`의 합으로 두면, 구간 `[i, i+k)`의 합은 `prefix[i+k] - prefix[i]`로 한 번에 구해진다.

`arr[0..i]`(i를 포함)의 합으로 둘 수도 있지만, 그러면 구간이 배열 맨 앞(`i = 0`)에서 시작할 때 `prefix[i-1]`이 없어 따로 분기해야 한다. `arr[0..i-1]`(i를 포함하지 않는) 쪽으로 한 칸 밀어 `prefix[0] = 0`을 "인덱스 0 앞까지의 합"으로 두면, 맨 앞에서 시작하는 구간도 예외 없이 `prefix[i+k] - prefix[i]` 하나의 식으로 처리된다. [별 세기](/lab/engineering/algorithm/star-count/)에서 사진 바깥을 0으로 취급해 경계 체크를 없앤 것과 같은 방식이다.

```java
int[] prefix = new int[arr.length + 1];
for (int i = 0; i < arr.length; i++) {
    prefix[i + 1] = prefix[i] + arr[i];
}

int max = 0;
for (int i = 0; i <= arr.length - k; i++) {
    int sum = prefix[i + k] - prefix[i];
    if (sum > max) max = sum;
}
```

복잡도: 시간 O(N)(프리픽스 합 구성 O(N) + 질의 N−K+1번 각 O(1)), 공간 O(N)(프리픽스 합 배열). 시도 2와 시간 복잡도는 같지만 입력 크기만큼의 배열을 추가로 쓴다. 이번처럼 창 크기 K가 고정이고 구간 합을 한 번만 구하면 시도 2가 더 가볍지만, 같은 배열에 서로 다른 구간 합을 반복해서 묻는 상황이라면 프리픽스 합 쪽이 유리하다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| 1. 창마다 처음부터 합산 | 겹치는 구간도 매번 다시 더함 | O(N×K) | 정답, 큰 입력에서 시간 초과 우려 |
| **2. 겹치는 부분 재사용 (채택)** | 빠지는 값 빼고 들어오는 값 더함 | O(N) | 정답, 선형 시간 |
| 다른 방법. 프리픽스 합 | 구간 합을 O(1) 질의로 미리 준비 | O(N) 시간, O(N) 공간 | 정답, 반복 질의에 유리 |

**채택: 시도 2.** 제약(N ≤ 100,000)에서 N×K는 최악 N²/4까지 늘어나 시간 제한이 불안하지만, 겹치는 구간을 재사용하면 추가 공간 없이 선형 시간으로 끝난다.

- 연속된 구간(창)이 한 칸씩 움직이며 합이나 개수 등을 구할 때, 창 사이에 **겹치는 부분이 있다면 다시 계산하지 말고 재사용**한다 — 빠지는 값을 빼고 들어오는 값만 더하면 된다.
- 같은 구간 합을 **한 번만 구하는지, 여러 번 반복해서 구하는지**가 슬라이딩 윈도우와 프리픽스 합 중 어느 쪽이 적합한지를 가른다.
