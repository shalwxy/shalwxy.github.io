## 문제

[이전 글(조직도를 세 가지 순서로 순회하기)](/lab/engineering/algorithm/1210035/)에서 쓴 것과 같은 조직도를 이번에는 너비 우선 탐색(BFS)으로 순회한다. 가까운 사람(자신으로부터 거쳐야 하는 단계 수가 적은 사람)부터 순서대로 방문하며 번호를 출력한다.

{% include figure image_path="/assets/img/lab/org-chart-binary-tree.svg" alt="7명이 삼각형 모양으로 배치된 조직도. 맨 위 1 아래로 2와 3이, 2 아래로 4와 5가, 3 아래로 6과 7이 선으로 연결된다" caption="이전 글과 같은 조직도" %}

이 조직도를 아래 두 가지 형태로 출력한다.

- 방문한 순서대로 사람 번호를 한 줄에 출력
- 몇 단계(레벨)에 있는 사람들인지 레벨별로 묶어서 출력

```
출력
BFS 순서: 1 2 3 4 5 6 7
레벨별:
0 : 1
1 : 2 3
2 : 4 5 6 7
```

> 출처: 인프런 [자바(Java) 알고리즘 문제풀이 입문: 코딩테스트 대비](https://www.inflearn.com/course/자바-알고리즘-문제풀이-코테대비)의 재귀 단원 연습문제를 소재만 바꿔 재구성했다.

## 공통 코드

```java
import java.util.LinkedList;
import java.util.Queue;

class Node {
    int val;
    Node left;
    Node right;

    Node(int val) {
        this.val = val;
    }
}

public class Main {
    public static Node root;

    public static void main(String[] args) {
        root = new Node(1);
        root.left = new Node(2);
        root.right = new Node(3);
        root.left.left = new Node(4);
        root.left.right = new Node(5);
        root.right.left = new Node(6);
        root.right.right = new Node(7);

        System.out.print("BFS 순서: ");
        bfsPlain(root);
        System.out.println();

        System.out.println("레벨별:");
        bfsByLevel(root);
    }
}
```

## 순서대로 출력하기

### 접근

큐에 루트를 넣고, 하나씩 꺼낼 때마다 그 자식들을 큐 뒤에 넣는다. 큐는 넣은 순서대로 꺼내지므로(선입선출), 이렇게만 해도 가까운 사람부터 차례로 꺼내진다.

```java
public static void bfsPlain(Node root) {
    Queue<Node> queue = new LinkedList<>();
    queue.offer(root);
    while (!queue.isEmpty()) {
        Node cur = queue.poll();
        System.out.printf("%d ", cur.val);
        if (cur.left != null) queue.offer(cur.left);
        if (cur.right != null) queue.offer(cur.right);
    }
}
```

### 결과

**성공** — `1 2 3 4 5 6 7` 출력.

### 분석

이전 글의 전위, 중위, 후위 순회는 재귀로 "한쪽 갈래를 끝까지 판 뒤 돌아오는" 순서였다. 이번엔 재귀 대신 큐를 쓰는데, 큐가 "먼저 들어온 게 먼저 나간다"는 성질 하나만으로 "가까운 사람부터" 순서가 저절로 만들어진다 — 루트를 넣고 그 자식들을 넣으면, 자식들이 전부 빠져나가기 전까지는 손자들이 먼저 빠져나갈 수 없기 때문이다.

## 레벨별로 묶어 출력하기

### 접근

레벨이 바뀌는 경계를 알려면, 지금 큐 안에 "이번 레벨에 속한 사람이 몇 명 있는지"를 미리 알아야 한다. 각 레벨이 시작될 때 큐의 크기(`size`)를 재두고, 딱 그 개수만큼만 꺼낸다.

```java
public static void bfsByLevel(Node root) {
    Queue<Node> queue = new LinkedList<>();
    queue.offer(root);
    int level = 0;
    while (!queue.isEmpty()) {
        int size = queue.size();
        System.out.printf("%d : ", level);
        for (int i = 0; i < size; i++) {
            Node cur = queue.poll();
            System.out.printf("%d ", cur.val);
            if (cur.left != null) queue.offer(cur.left);
            if (cur.right != null) queue.offer(cur.right);
        }
        level++;
        System.out.println();
    }
}
```

### 결과

**성공** — `0 : 1` / `1 : 2 3` / `2 : 4 5 6 7`이 각각 한 줄씩 출력된다.

### 분석

`size`를 반복문이 시작할 때 미리 재두는 게 핵심이다. 이번 레벨 사람들을 꺼내는 동안 그 자식들(다음 레벨)이 같은 큐에 계속 쌓이지만, `size`는 "꺼내기 시작한 시점의 개수"로 고정돼 있으므로 안쪽 반복문은 딱 이번 레벨 사람 수만큼만 돌고 멈춘다. 다음 레벨로 넘어가면 그때 다시 `size`를 재서, 레벨 경계가 자연스럽게 나뉜다.

## 정리

같은 큐 기반 탐색이라도, **"큐 크기를 레벨 단위로 끊어 읽느냐"**에 따라 출력 형태가 달라진다.

- 순서만 알면 되는 경우 — 가장 가까운 것부터 차례로 처리하기만 하면 될 때 — 는 `bfsPlain`처럼 큐에서 꺼내는 대로 바로 처리하면 된다.
- "몇 단계 떨어져 있는지"가 결과에 영향을 주는 경우(이 뒤에 이어지는 ["가장 가까운 말단까지의 거리 구하기"](/lab/engineering/algorithm/1210039/)처럼) — 는 레벨 경계를 알아야 하므로 `bfsByLevel`처럼 레벨마다 큐 크기를 재는 방식이 필요하다.
