## 문제

띠 여러 장을 바닥에서부터 겹쳐 놓고, 가위로 위에서 수직으로 잘라 몇 조각이 나오는지 구한다. 띠는 자신보다 긴 띠 위에만, 양 끝이 서로 겹치지 않게 완전히 포함되도록 놓인다. 각 띠는 가위질에 적어도 한 번은 잘리고, 가위질은 띠의 끝점과는 겹치지 않는다.

이 배치는 괄호로 표현할 수 있다. 서로 바로 붙어 있는 괄호 쌍 `()`는 가위질 한 번을 뜻하고, 띠의 왼쪽 끝은 `(`, 오른쪽 끝은 `)`로 나타낸다. `()`는 항상 가위질만을 뜻하며, 띠를 뜻하지 않는다.

{% include figure image_path="/assets/img/lab/strip-cut-pieces-diagram.svg" alt="띠 하나가 가장 아래에 있고 그 위에 겹쳐진 두 띠, 가장 위에 또 하나의 띠. 빨간 점선 화살표 3개가 위에서 아래로 가위질 위치를 가리킨다" caption="예제 배치: 띠는 겹친 깊이만큼 위로 그렸고, 빨간 화살표가 가위질이다" %}

괄호로 표현된 배치가 주어졌을 때, 잘린 띠 조각의 총 개수를 구한다.

- 괄호 문자의 개수는 최대 100,000
- 입력: 괄호로 된 배치 한 줄(공백 없음)
- 출력: 잘린 조각의 총 개수

```
입력                            출력
(((()()))(()))                 12
```

가장 안쪽 띠는 가위질 2번을 맞아 3조각이 되고, 그 띠를 감싸는 띠도 같은 가위질 2번에 함께 잘려 3조각이 된다. 오른쪽의 띠는 가위질 1번을 맞아 2조각이 되고, 이 모든 띠를 감싸는 가장 바깥 띠는 안쪽의 가위질 3번을 전부 맞아 4조각이 된다. 더하면 3+3+2+4=12.

## 공통 코드

아래 시도들은 입력을 읽고 결과를 출력하는 부분을 공유한다. 각 시도에서는 조각 수를 세는 `countPieces` 메서드만 다르다.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

    }

```

## 시도 1 — 열린 괄호 개수로 "지금 몇 겹인지" 세기 (채택)

### 접근

실제로 띠를 스택에 쌓을 필요는 없다. 지금 몇 장의 띠가 겹쳐 있는지(깊이)만 세면 충분하다. `(`를 만나면 깊이를 1 늘린다. `)`를 만났을 때 바로 앞 글자가 `(`였다면(`()`, 가위질) 깊이를 줄인 뒤 "지금 겹쳐 있는 띠 수"만큼 조각이 늘어난다고 본다. 바로 앞 글자가 `)`였다면(띠의 오른쪽 끝) 그 띠의 마지막 한 조각이 떨어져 나온 것이므로 조각 수를 1만 늘린다.

```java
public static int countPieces(String s) {
    int pieces = 0;
    int depth = 0;
    char prev = ' ';
    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (c == '(') {
            depth++;
        } else {
            depth--;
            if (prev == '(') {
                pieces += depth;
            } else {
                pieces++;
            }
        }
        prev = c;
    }
    return pieces;
}
```

### 결과

**성공** — 예제에서 `12` 출력.

복잡도: 시간 O(L), 공간 O(1). L은 괄호 문자열의 길이.

### 분석

가위질 한 번이 지나가는 자리에는 **그 순간 겹쳐 있는 띠 수만큼** 새로운 절단면이 생긴다. 띠 3장이 겹친 채로 가위질이 지나가면, 띠 3장이 동시에 한 번씩 잘려 조각이 3개 늘어난다. `depth`는 "지금 가위 아래 몇 장의 띠가 있는가"를 그대로 들고 있으므로, 가위질을 만날 때마다 `depth`를 그대로 더하면 된다.

띠의 오른쪽 끝(`(` 바로 뒤가 아닌 `)`)은 다르게 센다. 그 띠는 이미 안에 있던 가위질들에 의해 여러 조각으로 나뉘어 있고, 오른쪽 끝에서 끊어지는 **마지막 한 조각**만 아직 세어지지 않았다. 그래서 띠가 닫힐 때는 항상 1만 더한다 — 가위질을 몇 번 맞았든, 끝에서 떨어지는 마지막 조각은 하나뿐이기 때문이다.

## 다른 방법 — 깊이 대신 진짜 스택에 쌓기

깊이(정수 하나)만 세는 대신, [올바른 괄호 판별하기](/lab/engineering/algorithm/1210015/)에서처럼 `Stack<Character>`에 띠를 하나씩 실제로 쌓을 수도 있다. `depth`가 하던 일을 `stack.size()`가 그대로 대신한다.

```java
import java.util.Stack;

public static int countPieces(String s) {
    Stack<Character> stack = new Stack<>();
    int pieces = 0;
    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (c == '(') {
            stack.push(c);
        } else {
            stack.pop();
            if (s.charAt(i - 1) == '(') {
                pieces += stack.size();
            } else {
                pieces++;
            }
        }
    }
    return pieces;
}
```

복잡도는 시간 O(L)로 같지만, 공간은 `Stack` 객체와 그 안의 `Character` 박싱이 더해져 시도 1보다 무겁다. 지금 문제는 "지금 몇 장이 겹쳐 있는가"라는 **개수**만 알면 되고, 쌓여 있는 띠 하나하나가 서로 다른 어떤 값을 가졌는지는 묻지 않는다 — 그래서 값을 실제로 쌓을 필요 없이 정수 하나로 충분하다.

다만 나중에 "각 띠가 몇 번째로 놓였는지", "띠마다 다른 정보를 함께 기록해야 하는지"처럼 **열려 있는 개수 말고 각 띠의 정체 자체가 필요한 문제**로 확장된다면, 그때는 깊이 숫자만으로는 부족하고 진짜 스택에 각 띠의 정보를 쌓아야 한다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| **1. 깊이만 세기 (채택)** | `depth`가 "지금 겹친 띠 수" | 시간 O(L), 공간 O(1) | 정답 |
| 다른 방법. 진짜 스택에 쌓기 | `stack.size()`로 같은 역할 | 시간 O(L), 공간 O(L) | 정답, 각 띠의 정보까지 들고 다닐 수 있음 |

**채택: 시도 1.** 이 문제는 "지금 몇 겹인가"라는 개수만 있으면 풀리고, 겹친 띠 각각의 정체는 묻지 않는다. 그렇다면 스택 객체 없이 정수 하나로 충분하다.

- 가위질처럼 "지금 겹쳐 있는 개수만큼 한꺼번에 영향을 받는" 상황을 셀 때는, 그 개수를 변수 하나로 들고 있다가 그대로 더하면 된다.
- 괄호(또는 비슷한 중첩 구조)를 다룰 때, **"몇 개 열려 있는가"만 중요한지, 열려 있는 각각의 정체도 중요한지**를 먼저 구분한다. 전자면 정수 하나로 충분하고, 후자면 실제 스택이 필요하다.
