## 문제

이사짐 트럭에 짐을 실으려 한다. 포장된 상자가 순서대로 N개 있고, 각 상자의 무게(kg)가 주어진다. 트럭에는 상자를 포장된 순서 그대로 실어야 하며(순서를 바꾸면 안 되고), 상자 하나를 쪼개 여러 트럭에 나눠 실을 수도 없다 — 즉 1번 상자와 5번 상자를 같은 트럭에 실으려면, 그 사이의 2~4번 상자도 같은 트럭에 실어야 한다.

이사 업체는 트럭 M대를 쓰기로 했고, 트럭은 모두 같은 적재량으로 맞춰야 한다(트럭마다 크기가 다르면 제조나 대여 비용이 늘어난다). 짐을 모두 실을 수 있는 트럭의 최소 적재량을 구한다.

- 상자 수 N(1 ≤ N ≤ 1,000), 트럭 수 M(1 ≤ M ≤ N)
- 상자 하나의 무게는 10,000kg을 넘지 않는 자연수
- 입력: 첫 줄에 N과 M, 둘째 줄에 포장된 순서대로 상자의 무게
- 출력: 트럭의 최소 적재량

```
입력
9 3
4 8 5 3 9 6 7 2 5

출력
18
```

적재량이 18kg이면 `(4, 8, 5)`, `(3, 9, 6)`, `(7, 2, 5)`로 나눠 트럭 3대에 실을 수 있다(묶음의 무게 합은 각각 17, 18, 14로 모두 18 이하). 적재량을 17kg으로 줄이면 트럭이 4대 필요해져, 3대로는 부족하다.

## 공통 코드

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        int m = sc.nextInt();
        int[] weights = new int[n];
        for (int i = 0; i < n; i++) weights[i] = sc.nextInt();

        System.out.println(minCapacity(m, weights)); // 로직은 각 시도 참고
    }
}
```

## 시도 1 — 적재량을 이분 검색으로 찾기 (성공, 채택)

### 접근

트럭의 적재량 후보를 "상자 하나의 최대 무게"부터 "상자 전체 무게의 합"까지로 좁힌다(적재량이 가장 무거운 상자보다 작으면 그 상자를 아예 실을 수 없고, 전체 합이면 트럭 1대로 충분하다). 이 범위 안에서 이분 검색을 한다 — 적재량 후보 하나(`mid`)를 정해, 그 적재량으로 상자를 순서대로 나눠 실었을 때 트럭이 몇 대 필요한지(`truckCount`) 센다. 필요한 트럭 수가 M대 이하면 더 작은 적재량도 가능할 수 있으니 범위를 왼쪽으로, M대보다 많이 필요하면 적재량을 키워야 하니 오른쪽으로 좁힌다.

```java
import java.util.Arrays;

public static int minCapacity(int m, int[] weights) {
    int answer = 0;
    int lt = Arrays.stream(weights).max().getAsInt();
    int rt = Arrays.stream(weights).sum();

    while (lt <= rt) {
        int mid = (lt + rt) / 2;
        if (truckCount(weights, mid) <= m) {
            answer = mid;
            rt = mid - 1;
        } else {
            lt = mid + 1;
        }
    }
    return answer;
}

public static int truckCount(int[] weights, int capacity) {
    int count = 1;
    int sum = 0;
    for (int weight : weights) {
        if (sum + weight > capacity) {
            count++;
            sum = weight;
        } else {
            sum += weight;
        }
    }
    return count;
}
```

### 결과

**성공** — 예제에서 `18` 출력.

복잡도: 시간 O(N log S)(S는 상자 무게의 합. 이분 검색을 한 번 할 때마다 `truckCount`가 배열을 한 번 훑어 O(N)이고, 이분 검색 범위를 좁히는 데 O(log S)번 반복한다), 공간 O(1).

### 분석

이 문제는 "정답이 될 수 있는 값의 범위" 안에서 이분 검색을 한다는 점이 지금까지 다룬 이분 검색과 다르다. 이전 글([게임 랭킹에서 내 점수의 순위 찾기](/lab/engineering/algorithm/1210028/))에서는 정렬된 배열 안에 "이미 들어있는 값"을 찾았지만, 여기서는 배열 어디에도 "적재량 18"이라는 값이 들어있지 않다 — 적재량은 상자 무게들을 조합해서 만들 수 있는 수많은 후보 중 하나일 뿐이다.

이렇게 "배열 속에 있는 값을 찾는" 이분 검색이 아니라, 답 자체가 어딘가에 있다고 가정하고 그 답을 좁혀나가는 이분 검색을 **결정 알고리즘**(또는 매개변수 탐색, parametric search)이라 부르고, 다음 네 단계로 이뤄진다.

1. **답이 있다고 가정한다.** "트럭 M대로 충분한 최소 적재량이 어딘가에 존재한다"고 가정하고 시작한다.
2. **가능한 답의 범위를 추린다.** 적재량은 최소 "가장 무거운 상자의 무게"(그보다 작으면 그 상자를 아예 못 싣는다)부터, 최대 "상자 전체 무게의 합"(그 이상은 트럭 1대로 충분해서 더 키울 이유가 없다)까지로 좁힌다.
3. **그 범위 안에서 답을 이진 검색으로 줄여 나간다.** 범위의 가운데 값(`mid`)을 지금 확인해볼 답 후보로 고른다.
4. **그 후보가 유효한지 판단하기를 반복한다.** "이 적재량(`mid`)이면 트럭이 M대 이하로 충분한가?"를 확인해서, 유효하면(충분하면) 더 작은 값 쪽으로, 유효하지 않으면(부족하면) 더 큰 값 쪽으로 범위를 좁히고 3~4단계를 되풀이한다.

이 네 단계가 성립하려면 "범위를 반으로 쪼개도 되는가", 즉 단조성이 있어야 한다. 적재량이 커질수록 필요한 트럭 수는 줄어들거나 그대로고(적재량이 크면 더 많은 상자를 한 트럭에 몰아 실을 수 있으니까), 적재량이 작아질수록 필요한 트럭 수는 늘어나거나 그대로다. 즉 "적재량 → 필요한 트럭 수"라는 관계가 **한쪽으로만 움직인다**(적재량을 키우면 트럭 수는 절대 늘지 않는다). 이런 단조성이 있기 때문에, 후보 하나를 확인해본 결과만으로 범위의 절반을 통째로 버릴 수 있다.

여기서 그 "예/아니오 질문"을 판단하는 역할이 `truckCount` 메서드다. 적재량(`capacity`)이 주어지면, 상자를 순서대로 보면서 지금까지 실은 무게(`sum`)에 다음 상자를 더했을 때 적재량을 넘기면 새 트럭을 하나 꺼내고(`count++`), 넘기지 않으면 같은 트럭에 계속 싣는다 — 이렇게 세어본 트럭 수가 M 이하면 "이 적재량으로 충분하다"(예), 초과하면 "부족하다"(아니오)라는 뜻이다.

`minCapacity`의 이분 검색 루프는 이 예/아니오 결과에 따라 범위를 좁힌다. "충분하다"(`truckCount(...) <= m`)면 지금의 `mid`를 일단 답 후보(`answer`)로 저장해두고, 더 작은 적재량도 가능한지 보려고 오른쪽 경계(`rt`)를 `mid - 1`로 줄인다. "부족하다"면 적재량을 키워야 하므로 왼쪽 경계(`lt`)를 `mid + 1`로 올린다. 이 과정을 `lt`와 `rt`가 교차할 때까지 반복하면, 마지막으로 저장된 `answer`가 "트럭 M대로 충분한 가장 작은 적재량"이 된다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| **1. 결정 알고리즘(이분 검색) (채택)** | 적재량 범위를 좁히며 "트럭 M대로 충분한가"를 반복 질문 | O(N log S) | 정답 |

**채택: 시도 1.** 적재량처럼 하나하나 다 시도해보려면 범위가 너무 넓은(최대 10,000×1,000 = 천만에 가까운 수 가운데 하나) 값을, 결정 알고리즘은 `log S`번의 예/아니오 질문만으로 찾아낸다.

- 이분 검색은 "정렬된 배열에서 값을 찾을 때"만 쓰는 게 아니다. **"이 값이면 조건을 만족하는가?"라는 예/아니오 질문에 단조로운 경계가 있는 모든 상황**에서, 그 경계(최솟값 또는 최댓값)를 찾는 데 쓸 수 있다 — 이게 결정 알고리즘이다.
- 결정 알고리즘을 쓰려면 먼저 두 가지를 확인해야 한다. ① 정답이 "어떤 값 이상(또는 이하)이면 항상 조건을 만족한다"는 단조성이 있는가, ② 특정 값 하나가 주어졌을 때 "조건을 만족하는가"를 빠르게 판단하는 함수(여기서는 `truckCount`)를 만들 수 있는가.
- 탐색 범위(`lt`, `rt`)를 정할 때는 "절대 답이 될 수 없는 값"을 먼저 제외해 가장 좁은 범위로 시작한다 — 여기서는 가장 무거운 상자보다 작은 적재량(그 상자를 못 싣는다)과, 전체 합보다 큰 적재량(트럭 1대로 충분한데 더 키울 이유가 없다)을 제외했다.
