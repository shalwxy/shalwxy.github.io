## 문제

괄호 `(`와 `)`로만 이루어진 문자열이 주어진다. 모든 여는 괄호가 그보다 뒤에 오는 닫는 괄호와 올바른 순서로 짝을 이루면 `YES`, 아니면 `NO`를 출력한다.

- 문자열의 길이는 30을 넘지 않는다
- 입력: 괄호로 이루어진 문자열 한 줄
- 출력: 올바른 괄호면 `YES`, 아니면 `NO`

```
입력                출력
((())())(          NO
```

앞의 8글자 `((())())`만 보면 완전히 짝이 맞는다(1→2→3→2→1→2→1→0, 중간에 짝이 안 맞게 음수로 떨어지는 지점도 없다). 하지만 마지막 `(` 하나가 짝 없이 남아, 전체로 보면 올바른 괄호가 아니다.

## 공통 코드

아래 시도들은 입력을 읽고 결과를 출력하는 부분을 공유한다. 각 시도에서는 올바른 괄호인지 판별하는 `isValidParentheses` 메서드만 다르다.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String s = sc.next();

        System.out.println(isValidParentheses(s)); // 로직은 각 시도 참고
    }
}
```

## 시도 1 — 스택으로 짝을 맞춰보기 (채택)

### 접근

여는 괄호를 만나면 스택에 쌓아두고, 닫는 괄호를 만나면 스택에서 하나를 꺼내 짝을 맞춘다. 문자열을 끝까지 다 본 뒤에도 스택이 완전히 비어 있어야 모든 괄호가 짝을 이뤘다고 할 수 있다.

```java
import java.util.Stack;

public static String isValidParentheses(String s) {
    Stack<Character> stack = new Stack<>();
    for (char x : s.toCharArray()) {
        if (x == '(') {
            stack.push(x);
        }
        if (x == ')') {
            if (stack.isEmpty()) return "NO";
            stack.pop();
        }
    }
    return stack.isEmpty() ? "YES" : "NO";
}
```

### 결과

**성공** — 예제에서 `NO` 출력.

복잡도: 시간 O(L), 공간 O(L)(최악의 경우 모든 글자가 여는 괄호라 스택에 전부 쌓인다). L은 문자열 길이.

### 분석

왜 스택이 맞는 도구인지는 "닫는 괄호 하나는 누구와 짝을 지어야 하는가"를 생각해보면 드러난다. `((`처럼 괄호 두 개가 열린 상태에서 `)`를 만나면, 먼저 열린 바깥 괄호가 아니라 **가장 나중에 열린 안쪽 괄호**와 먼저 짝이 맞아야 한다. "가장 나중에 들어온 것을 가장 먼저 꺼낸다"는 동작이 정확히 스택이 하는 일이라서, 열린 괄호를 스택에 쌓아두면 닫는 괄호를 만날 때마다 맨 위(가장 최근에 열린 것)가 자동으로 짝지어진다.

문자열을 다 본 뒤 스택에 뭔가 남아있다면, 그건 끝까지 짝을 찾지 못한 여는 괄호가 있다는 뜻이다. 예제의 `((())())(`가 그 경우다 — 앞의 8글자는 완전히 짝이 맞아 스택을 다 비우지만, 마지막 `(` 하나가 다시 쌓인 채로 문자열이 끝나버린다. 그래서 반복문이 끝난 뒤에도 "스택이 비어 있는가"를 꼭 확인해야 한다.

## 다른 방법 — 괄호 종류가 하나뿐이라면 개수만 세기

이 문제의 괄호는 `(`와 `)` **한 종류뿐**이다. 스택에 쌓이는 값도 항상 `'('` 하나뿐이라, 꺼낼 때 "무엇을 꺼냈는지"는 볼 필요가 없다 — 중요한 건 "지금 짝이 안 맞은 여는 괄호가 몇 개 남아 있는가"라는 **개수**뿐이다. 그렇다면 괄호를 실제로 쌓아두지 않고, 그 개수만 정수 하나로 세도 충분하다.

```java
public static String isValidParentheses(String s) {
    int depth = 0;
    for (char x : s.toCharArray()) {
        if (x == '(') depth++;
        if (x == ')') {
            depth--;
            if (depth < 0) return "NO";
        }
    }
    return depth == 0 ? "YES" : "NO";
}
```

`depth`가 스택의 "크기"만 들고 다니는 셈이다. 여는 괄호를 만나면 1 늘리고, 닫는 괄호를 만나면 1 줄인다. 도중에 0 미만으로 떨어지면 짝지을 여는 괄호가 없다는 뜻이니 그 자리에서 `NO`, 다 본 뒤 정확히 0이면 `YES`다.

복잡도는 시간 O(L)로 같지만 공간은 O(1)로 줄어든다 — `Stack` 객체와 그 안의 문자들을 저장할 필요가 없다. 다만 이 방법은 **괄호 종류가 하나뿐이라서** 성립한다. `(`, `[`, `{`처럼 종류가 여러 개로 늘어나면, 닫는 괄호를 만났을 때 "짝이 맞는 종류의 여는 괄호가 가장 최근에 열렸는가"까지 확인해야 하므로, 그때는 실제 스택으로 어떤 종류가 열려 있었는지 기억해야 한다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| **1. 스택으로 짝 맞추기 (채택)** | 여는 괄호를 쌓고, 닫는 괄호마다 하나씩 꺼냄 | 시간 O(L), 공간 O(L) | 정답 |
| 다른 방법. 개수만 세기 | 스택 대신 정수 하나로 깊이만 추적 | 시간 O(L), 공간 O(1) | 정답, 괄호 종류가 하나일 때만 |

**채택: 시도 1.** 지금은 괄호가 한 종류뿐이라 둘 다 정답을 내지만, 스택은 종류가 여러 개로 늘어나도 그대로 확장되는 범용적인 풀이라 먼저 익혀둘 가치가 있다.

- "가장 나중에 연 것이 가장 먼저 닫혀야 한다"는 중첩 구조는 스택(LIFO)과 그대로 맞아떨어진다. 짝을 맞추는 문제에서 "가장 최근 것부터 처리"가 필요하면 스택을 먼저 떠올린다.
- 반복문이 끝난 뒤 자료구조가 비어 있는지 확인하는 걸 잊기 쉽다. "모두 짝지어졌다"는 조건은 끝까지 다 봤을 때뿐 아니라, **남은 게 없어야** 완성된다.
- 스택에 쌓이는 값의 종류가 하나뿐이라면, 꺼낸 값을 들여다볼 필요가 없다 — 그럴 때는 스택 전체를 정수 하나(쌓인 개수)로 대체할 수 있다.
