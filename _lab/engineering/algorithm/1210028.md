## 문제

온라인 게임의 랭킹 게시판에는 N명의 점수가 순서 없이 올라와 있다. 이 점수를 오름차순으로 정렬했을 때, 특정 플레이어의 점수 M이 몇 번째에 있는지 이분 검색으로 구한다. 점수는 모두 서로 다르다.

- 참가자 수 N(3 ≤ N ≤ 1,000,000), 찾는 점수 M(참가자 중 한 명의 점수)
- 입력: 첫 줄에 N과 M, 둘째 줄에 N명의 점수
- 출력: 오름차순 정렬 후 M의 위치(1번째부터 센다)

```
입력
8 63
45 112 78 29 91 63 134 107

출력
3
```

점수를 오름차순으로 정렬하면 `29 45 63 78 91 107 112 134`이고, 63은 그중 3번째다.

## 공통 코드

아래 시도들은 입력을 읽고 결과를 출력하는 부분을 공유한다. 각 시도에서는 순위를 구하는 `findRank` 메서드만 다르다.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        int m = sc.nextInt();
        int[] scores = new int[n];
        for (int i = 0; i < n; i++) scores[i] = sc.nextInt();

        System.out.println(findRank(m, scores)); // 로직은 각 시도 참고
    }
}
```

## 시도 1 — 정렬 후 이분 검색 (성공, 채택)

### 접근

점수를 오름차순으로 정렬한 뒤, 찾는 점수 M이 있을 법한 범위(`lt`~`rt`)를 반씩 좁혀가며 찾는다. 가운데 값이 M보다 크면 왼쪽 절반만, 작으면 오른쪽 절반만 남기고, 같으면 그 자리가 답이다.

```java
import java.util.Arrays;

public static int findRank(int key, int[] scores) {
    int lt = 0;
    int rt = scores.length - 1;
    int mid = -1;

    Arrays.sort(scores);

    while (lt <= rt) {
        mid = (lt + rt) / 2;
        if (key < scores[mid]) {
            rt = mid - 1;
        } else if (key > scores[mid]) {
            lt = mid + 1;
        } else {
            break;
        }
    }

    return mid + 1;
}
```

### 결과

**성공** — 예제에서 `3` 출력.

복잡도: 시간 O(N log N)(정렬이 가장 오래 걸리고, 이분 검색 자체는 O(log N)), 공간 O(1)(정렬은 배열 안에서 이뤄진다). 실제로 점수 100만 개를 넣어 검색해봐도 54ms 안팎이다(대부분 정렬에 쓰인다).

### 분석

범위를 반씩 좁혀나가므로, 검색 구간은 `lt`와 `rt`가 만날 때까지 매번 절반으로 줄어든다. 그래서 이분 검색 자체는 O(log N)이지만, 전체 복잡도는 그 앞에서 한 번 수행하는 정렬(O(N log N))이 좌우한다. 데이터가 이미 정렬된 상태로 주어진다면(예: 정렬된 랭킹을 계속 들고 있다가 새 점수가 들어올 때마다 위치를 찾는 경우), 정렬을 건너뛰고 O(log N)만으로 찾을 수 있다는 게 이분 검색의 진짜 장점이다.

## 다른 방법 — 나보다 낮은 점수 세기

이 문제는 "몇 번째인지"만 구하면 되므로, 사실 정렬도 이분 검색도 필요 없다. 점수들을 한 번 훑으면서 M보다 작은 점수가 몇 개인지 세면, 그 개수에 1을 더한 값이 바로 M의 순위다(중복이 없다고 보장되므로).

```java
public static int findRank(int key, int[] scores) {
    int rank = 1;
    for (int score : scores) {
        if (score < key) {
            rank++;
        }
    }
    return rank;
}
```

복잡도는 시간 O(N)(한 번만 훑는다), 공간 O(1) — 정렬이 필요 없어 시도 1보다 점근적으로도 더 빠르다. 실제로 점수 100만 개에서 돌려보면 1ms도 안 걸린다.

다만 이 방법은 "몇 번째인지"라는 **결과**만 구할 뿐, 문제가 요구하는 **이분 검색이라는 방법 자체**는 전혀 쓰지 않는다. 순위 하나만 필요한 상황이라면 이쪽이 더 간단하고 빠르지만, 이분 검색 구현 자체가 목적이거나(이 문제처럼), 정렬된 데이터에서 반복적으로 여러 값을 찾아야 하는 상황이라면 시도 1이 맞다.

## 정리

| 시도 | 핵심 | 복잡도 | 결과 |
|---|---|---|---|
| **1. 정렬 후 이분 검색 (채택)** | 범위를 절반씩 좁혀가며 찾기 | O(N log N) | 정답 |
| 다른 방법. 작은 값 개수 세기 | M보다 작은 값의 개수 + 1 | O(N) | 정답, 이분 검색을 쓰지 않음 |

**채택: 시도 1.** 이 문제는 이분 검색으로 위치를 구하라고 명시하고 있고, 정렬된 데이터에서 값을 찾는 이분 검색의 핵심 패턴(범위를 절반씩 좁히기)을 그대로 보여준다. N이 100만이어도 정렬과 이분 검색 모두 충분히 빠르다.

- "몇 번째인지"처럼 결과만 필요한 문제는, 꼭 정렬이나 검색을 거치지 않고도 더 빠르게 구할 수 있는 경우가 있다. 다만 문제가 특정 알고리즘(여기서는 이분 검색)의 구현 자체를 요구한다면, 결과가 같아도 그 알고리즘으로 풀어야 한다.
- 이분 검색은 "이미 정렬된 데이터"에서 빛을 발한다. 정렬까지 포함한 전체 복잡도는 정렬 비용(O(N log N))이 좌우하지만, 정렬된 데이터를 두고 여러 번 찾아야 한다면 정렬은 한 번만 하고 찾을 때마다 O(log N)만 들면 된다.
