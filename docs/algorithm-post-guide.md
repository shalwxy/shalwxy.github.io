## 섹션별 규칙

### 문제
- **자기 말로 다시 쓴다.** 원문을 복사하지 않는다. 소재·수치·예제를 바꿔 재구성하고, 바꾼 예제의 정답은 직접 계산해 검증한다.
- 포함할 것: 문제 설명, 제약 조건(범위·크기), 입력·출력 형식, 예제 입출력, 예제 해설(왜 그 답인지 2~3칸 정도 짚기).
- 끝에 출처를 인용문(`>`)으로 남긴다. 강의·문제 링크를 걸되 `?cid=` 같은 추적 파라미터는 뺀다.

### 공통 코드
- 입력 읽기, 방향 상수(`DX`/`DY`) 등 모든 시도가 공유하는 코드를 **한 번만** 보여준다.
- 각 시도에서는 핵심 로직(세는 부분, 탐색 부분)만 보인다.

### 시도 n
제목은 `시도 n — 한 줄 요약`. 하위는 반드시 **접근 → 결과 → 분석** 순서.

| 하위 섹션 | 내용 | 넣지 않을 것 |
|---|---|---|
| 접근 | 아이디어 1~2문장 + 핵심 코드 | 평가 |
| 결과 | ① 판정 `**성공**`/`**실패**` — 사실 한 구절 ② 복잡도(성공 시) ③ 관찰 | 평가, 다음 시도 동기 |
| 분석 | 왜 그런 결과가 나왔나 + 다음 시도로 넘어가는 동기. 마지막 시도는 "얻은 것" | 앞 단락 반복 |

- **결과의 판정은 사실만.** "코드가 길어졌다"는 분석 몫.
- **복잡도는 시도마다.** 앞 시도와 같으면 "왜 안 변했는지" 한 구절(예: "방향 루프가 생겼지만 길이가 상수라 같다"). 실패한 시도는 생략.
- **분석은 짧게.** 핵심 한 문장 + 근거. 같은 말을 단락 바꿔 반복하지 않는다.
- 코드와 설명이 어긋나지 않게(설명에서 `DX.length`를 권하면 코드도 `DX.length`).

### 다른 방법 (선택)
시도 구조를 강제하지 않는다. 코드 + 장단점 + 복잡도 한 줄.

### 채택 표시
가장 좋은 시도는 세 곳에서 한눈에 보이게 한다.
- 시도 제목 끝에 `(채택)`: `## 시도 3 — 방향 배열 + 플래그 (채택)`
- 정리 표에서 그 행을 굵게 + `(채택)`
- 정리 표 바로 아래 한 줄: `**채택: 시도 n.** 왜 이것이 가장 좋은지 한 문장`

### 정리
- 표: 시도 · 핵심 · 복잡도 · 결과 (채택 행은 굵게)
- 채택 한 줄
- 교훈 2~3개. 이 문제를 넘어 다른 문제에도 쓸 수 있는 것만.

## 태그
- **큰 주제 단위로 2개 정도.** 예: `알고리즘`, `배열`.
- 경계 처리·방향 배열·플래그 같은 세부 개념은 태그가 아니라 글 안에서 다룬다.

## 코드
- 언어: Java.
- 시도 간 변수·배열 이름을 통일한다(`sky`, `count`, `isStar` …).
- 방향 배열은 루프 변수와 짝지어 `DI`/`DJ`(i에 더할 값, j에 더할 값)로 쓴다. `DX`/`DY`는 x가 행인지 열인지 헷갈려 피한다. 공통 코드에서 "d번째 이웃 = (i + DI[d], j + DJ[d])"와 순서(위·아래·왼쪽·오른쪽)를 한 줄로 밝힌다.
- 비교 연산자와 설명을 일치시킨다. 코드가 `>=`면 글도 "자신 이상"으로 쓴다("나보다 밝은"은 `>`로 읽힌다).
- 들여쓰기 4칸, 한 줄이 길면 `&&` 앞에서 줄바꿈.
